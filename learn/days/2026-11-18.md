# 2026년 11월 18일 C++·Qt 수업 정리

C++ 오류 처리와 C·C++ 링킹을 마무리하고 Qt 실습을 시작했다. 오전에는 Qt 예제를 Ubuntu·Windows·Raspberry Pi에서 빌드했고, 오후에는 USB 카메라의 MJPEG 영상을 Qt Widgets 앱에 2×2로 표시했다.

## 09시 · Qt 설치와 실행 중 오류 처리

- PC에서는 Qt 6.8.3과 Qt Creator를 설치했다. Windows의 일반 Widgets 예제에는 MinGW 키트를 사용했고, Raspberry Pi 실습 보드에서는 기존 Qt 5 환경을 사용했다. 호스트에서 ARM용 바이너리를 만드는 **크로스 컴파일**도 소개했다.
- 문법이나 타입 오류는 컴파일 과정에서 발견된다. 실행 중 사용자가 분모에 0을 입력하는 경우처럼 입력값에 따라 생기는 오류는 연산 전에 조건을 검사해 처리한다.
- 거듭제곱 실습에서는 반복 곱셈으로 `2^3`을 계산하면 8이 나온다. 같은 루프에 지수 −3을 넘기면 곱셈이 한 번도 실행되지 않아 초기값 1을 반환한다. 이 예제의 정수 결과 함수는 음수 지수를 처리 범위에서 제외했다.
- 오류를 `-1` 같은 값으로 반환하면, 정상 결과도 `-1`이 될 수 있는 함수에서는 두 경우가 겹친다. 수업에서 개선한 예제는 `bool`로 성공 여부를 반환하고 참조 매개변수 `int& result`에 계산 결과를 기록했다. 호출자는 성공한 경우에 결과를 사용한다.

## 10~11시 · `extern "C"`와 Qt 빌드

C++의 이름 장식(name mangling)은 함수 이름에 매개변수 타입과 같은 정보를 반영한다. C로 컴파일한 함수의 선언을 C++에서 사용하려면 그 선언에 **C 언어 링키지**를 지정한다. 이름 장식의 구체적인 형식은 컴파일러와 대상 플랫폼에 따라 달라진다. [Microsoft C/C++ 이름 장식](https://learn.microsoft.com/en-us/cpp/build/reference/decorated-names) · [C 함수용 공용 헤더](https://learn.microsoft.com/en-us/cpp/build/exporting-c-functions-for-use-in-c-or-cpp-language-executables)

```c
/* ops.h */
#ifndef OPS_H
#define OPS_H

#ifdef __cplusplus
extern "C" {
#endif

int add(int a, int b);

#ifdef __cplusplus
}
#endif

#endif
```

예를 들어 `ops.c`에서 이 헤더를 포함하고 `add`를 정의한 뒤, `main.cpp`에서 같은 헤더를 포함해 `add(3, 4)`를 호출한다. GCC 환경에서는 `gcc -c ops.c -o ops.o`로 C 오브젝트 파일을 만들고, `g++ main.cpp ops.o -o demo`로 C++ 소스와 함께 링크한다.

| 작업 | 수업에서 사용한 방법 |
| --- | --- |
| 터미널에서 빌드 | `.pro`가 없으면 `qmake -project`로 만들고 필요한 모듈을 확인한다. `qmake`가 `.pro`를 읽어 Makefile을 생성하고, `make`로 빌드한다. |
| Qt 버전 확인 | `qmake -v`로 현재 선택된 Qt 버전을 확인한다. 설치한 Qt가 잡히지 않으면 해당 버전의 `bin` 경로가 현재 셸의 `PATH`에 반영됐는지 확인한다. |
| Qt Creator에서 빌드 | `.pro`를 열고 대상 키트를 선택해 **Configure Project**를 실행한다. 키트에 맞는 컴파일러와 Qt 라이브러리로 Debug 또는 Release를 빌드한다. |
| 빌드 시스템 구분 | 기존 Qt 예제와 카메라 뷰어에는 qmake를 사용했다. CMake 기반 예제를 열 때는 CMake와 Ninja 설치 여부를 확인했다. |

Ubuntu와 Windows에서는 제공된 기본 블록 게임 예제를 각 플랫폼의 키트로 빌드했다. Raspberry Pi에서는 장치 입력 코드가 추가된 예제를 보드 환경에서 별도로 빌드했다. [10~11시 전사본](<26 11 18/lecture/10.txt>) · [qmake 실행 방식](https://doc.qt.io/qt-6.8/qmake-running.html)

## 12시 · Raspberry Pi 키 입력과 LED 출력

1. LED·키 커널 모듈을 올리고 `lsmod`로 로드 여부를 확인했다. `/proc/devices`에서 주 번호를 확인해 앱이 여는 경로에 문자 장치 노드를 준비했다.
2. Qt 래퍼 클래스는 `QFile`을 읽기·쓰기 모드로 열고 `handle()`로 파일 디스크립터를 얻었다. `QSocketNotifier`에 디스크립터를 등록하면 읽을 데이터가 준비됐을 때 `activated` 시그널이 발생한다.
3. 키를 읽는 슬롯이 키 값을 읽어 시그널을 보내면 게임 보드가 기존 이동·회전·시작·일시정지 함수를 호출한다. 보드에서 LED 갱신 시그널을 보내면 연결된 슬롯이 값을 장치에 쓴다.
4. 장치 파일을 열지 못하면 예제는 경고를 띄우고 키보드 입력으로 계속 실행할 수 있었다.

**시그널**은 객체에서 발생한 일을 알리고, **슬롯**은 그 알림을 받아 동작하는 함수다. `QObject::connect`가 둘을 연결한다. 이 예제에서 키 읽기와 LED 쓰기는 각각 별도의 연결이다. [12시 전사본](<26 11 18/lecture/12.txt>) · [Qt 시그널과 슬롯](https://doc.qt.io/qt-6.8/signalsandslots.html) · [QSocketNotifier](https://doc.qt.io/qt-6.8/qsocketnotifier.html)

## 14~15시 · Qt Widgets 카메라 뷰어

| 단계 | 실습 내용 |
| --- | --- |
| 영상 송출 | Raspberry Pi에 USB 웹캠을 연결하고 MJPG-streamer의 `start.sh`를 실행했다. Qt 작업에 들어가기 전에 브라우저에서 HTTP 스트림이 재생되는지 확인했다. |
| 프로젝트 생성 | Qt Creator에서 **Qt Widgets Application**을 만들고 qmake, 기본 클래스 `QWidget`, Designer 폼 생성을 선택했다. `main.cpp`는 `QApplication`과 위젯을 생성하고, `show()`로 창을 표시한 뒤 `app.exec()`로 이벤트 루프를 실행한다. |
| 화면 배치 | Designer에서 `.ui` 파일을 열고 바깥쪽 세로 레이아웃 안에 가로 레이아웃 두 줄을 뒀다. 각 줄에 뷰 두 개를 넣어 2×2로 배치하고, 각 위치의 레이아웃에 고유한 객체 이름을 붙였다. |
| 영상 표시 | `.pro`에 `QT += webenginewidgets`를 추가하고 `QWebEngineView`를 썼다. 일반 웹페이지로 먼저 확인한 뒤 스트림 주소로 바꾸고, 뷰 네 개에 각각의 주소를 설정할 수 있도록 구성했다. |
| 빌드 확인 | Windows의 일반 Widgets 예제에는 MinGW를 썼고 WebEngine 카메라 뷰어는 Ubuntu에서 실습했다. `.pro`나 `.ui` 변경이 반영되지 않을 때는 객체 이름을 확인하고 qmake를 다시 실행하거나 프로젝트를 정리한 뒤 다시 빌드했다. |

실습 흐름은 `USB 웹캠 → Raspberry Pi의 MJPG-streamer → HTTP 스트림 → Qt의 QWebEngineView`다. 위젯 생성자에서 폼을 먼저 초기화한 뒤 웹 뷰를 레이아웃에 추가하고, `view->load(QUrl{streamUrl});`로 주소를 연다. ## 16시 · 스트림 인증과 `QUrl`

- MJPG-streamer의 HTTP 출력 플러그인에 `-c` 옵션으로 실습용 인증을 추가했다. 기존 명령을 수정하는 과정에서 카메라 입력 플러그인 옵션을 빠뜨리면 영상이 나오지 않는 것도 확인했다.
- Qt 쪽에서는 스트림 주소로 `QUrl` 객체를 만든 뒤 `setUserName()`, `setPassword()`로 인증 정보를 넣는 방식을 시연했다. 한 뷰에만 설정했을 때 인증 정보가 설정된 화면만 표시됐다.
- 주소를 `QUrl streamUrl{address};`처럼 직접 초기화하며 `explicit` 생성자를 복습했다. Qt 6.8.3에서 `QString`을 받는 `QUrl` 생성자는 `QT_NO_URL_CAST_FROM_STRING` 설정이 켜진 경우 `explicit`으로 선언된다. 직접 초기화는 이 경우에도 사용할 수 있다.

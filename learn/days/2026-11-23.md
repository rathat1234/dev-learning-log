# 2026년 11월 23일 C++·Qt 수업 정리

Qt IoT 클라이언트에서 소켓 탭을 장치 제어, 홈 제어, 센서 차트 탭에 연결했다. 탭 사이의 `connect()`는 각 탭의 객체에 접근할 수 있는 `MainWidget`에 모았다. 오전에는 Raspberry Pi의 LED와 키를 원격에서 제어·확인하고 스마트홈 버튼을 장치 응답과 동기화했다. 오후에는 센서 수신값을 시간축에 그리는 실습을 했다. [Qt 시그널과 슬롯](https://doc.qt.io/qt-6.8/signalsandslots.html)

| 탭 | 역할 | 데이터 흐름 |
| --- | --- | --- |
| 1 · 장치 제어 | LED 출력, 물리 스위치와 체크박스 상태 처리 | 탭 2에서 LED 값을 받고, 변경된 키 상태를 탭 2로 보낸다. |
| 2 · 소켓 클라이언트 | IoT 서버 접속, 송수신, 수신 명령 분류 | 송신 탭의 메시지를 서버에 보내고, 수신한 명령을 해당 탭에 전달한다. |
| 3 · 홈 제어 | 램프와 플러그 버튼 표시 및 제어 | 탭 2로 ON/OFF 명령을 보내고, 수신한 응답에 맞춰 아이콘과 색상을 갱신한다. |
| 4 · 센서 차트 | 조도·온도·습도 표시 | 탭 2에서 받은 센서값을 수신 시간 기준으로 누적한다. |

## 09시 · 원격 LED 제어와 키 상태 회신

- **LED 수신**. 다른 클라이언트에서 `[수신자ID]LED@0x00`, `[수신자ID]LED@0xAA` 같은 명령을 보내면 탭 2가 받는다. 수신 문자열의 `[`와 `]`를 `@`로 바꿔 `split('@')` 하면 빈 항목, ID, 명령, 인수 순서의 `QStringList`가 된다. `LED` 명령의 인수는 `toInt(&ok, 16)`로 변환하고 `ok`로 변환 성공을 확인한다. 다이얼에 전달할 LED 값의 범위는 0~255다. [09시 전사본 12~24분](<26 11 23/lecture/26 11 23 09-_original.txt>) · [QString](https://doc.qt.io/qt-6.8/qstring.html)
- **LED 출력**. `MainWidget`에서 탭 2의 LED 시그널을 탭 1의 `QDial::setValue()`에 연결했다. 다이얼 값이 바뀌면 기존 `valueChanged(int)` 연결을 따라 LCD, 진행 바, 실제 LED가 함께 갱신된다. 시연에서는 탭 1의 공개 getter로 다이얼 포인터를 얻었다. 탭 1에 슬롯을 두고 그 안에서 `setValue()`를 호출하는 방식도 설명했다. [09시 전사본 16~27분](<26 11 23/lecture/26 11 23 09-_original.txt>) · [11월 20일 정리](2026-11-20.md)
- **키 송신**. 물리 스위치를 누르거나 화면 체크박스를 클릭하면 탭 1에서 8비트 키 상태를 갱신한다. `QString::number(값, 16)`으로 16진수 문자열을 만들고 `0x`를 붙여 지정한 상대에게 보낸다. 시연 코드에서는 한 자리 값도 그대로 전송했다. 탭 1의 송신 시그널은 `MainWidget`에서 탭 2가 갖고 있는 소켓 객체의 기존 송신 슬롯에 연결했다. [09시 전사본 27~35분](<26 11 23/lecture/26 11 23 09-_original.txt>)
- **보드 테스트**. 디바이스 파일과 드라이버 모듈을 확인한 뒤 Qt 앱과 별도 Linux 클라이언트를 서로 다른 ID로 서버에 접속시켰다. 배포받은 소스를 쓸 때는 서버 주소와 로그인 ID를 실습 환경에 맞게 바꾼다. 같은 ID로 다시 접속하면 기존 연결이 끊길 수 있다. [09시 전사본 05~14분](<26 11 23/lecture/26 11 23 09-_original.txt>)

## 10시 · Designer로 홈 제어 화면 구성

1. 세 번째 탭을 `QWidget` 기반 **Qt Designer Form Class**로 만든다. 방 배경과 램프·플러그의 ON/OFF PNG를 `.qrc`에 등록하고, qmake 프로젝트의 `.pro`에서 `RESOURCES` 항목을 확인한다. [10시 전사본 00~16분](<26 11 23/lecture/26 11 23 10~_original.txt>) · [Qt 리소스 시스템](https://doc.qt.io/qt-6.8/resources.html)
2. `QScrollArea` 안에 `QLabel`을 두고 `pixmap`에 방 이미지를 지정한다. 화면이 이미지보다 작으면 스크롤해서 나머지 영역을 볼 수 있다. 배경이 버튼을 가리면 Designer에서 배경 라벨에 **Send to Back**을 적용한다. [10시 전사본 17~26분](<26 11 23/lecture/26 11 23 10~_original.txt>)
3. `QPushButton`의 `checkable`을 켜고 초기 `checked`는 끈다. `icon`의 **Normal Off**와 **Normal On**에 각각 OFF·ON 이미지를 지정한다. 시연에서는 아이콘 크기를 70×70으로 조정했다. 폼을 만든 뒤 `MainWidget`에서 객체를 생성해 세 번째 탭에 배치한다. [10시 전사본 20~38분](<26 11 23/lecture/26 11 23 10~_original.txt>) · [QIcon](https://doc.qt.io/qt-6.8/qicon.html)

## 11~12시 · 스마트홈 명령 전송과 응답 반영

- **송신**. 탭 3의 버튼 클릭 슬롯이 `clicked(bool)`의 값을 이용해 `LAMPON` 또는 `LAMPOFF`를 선택한다. 램프 명령에서는 ON/OFF까지 한 토큰으로 보낸다. 탭 3이 시그널로 문자열을 넘기면 탭 2의 기존 소켓 송신 슬롯이 서버에 전송한다. 클릭 직후에는 `setChecked()`로 이전 체크 상태를 복원해 응답을 기다린다. [11시 전사본 00~15분](<26 11 23/lecture/26 11 23 11~_original.txt>)
- **수신**. 탭 2는 `indexOf()`로 램프 명령이 있는지 확인한다. 찾으면 위치를 반환하고, 없으면 `-1`을 반환한다. 탭 2가 분리한 문자열 목록을 탭 3의 수신 슬롯으로 넘기면, 탭 3이 명령을 정확히 비교해 `setChecked(true/false)`로 아이콘을 바꾼다. 시연에서는 `QPalette`로 ON은 빨간색, OFF는 파란색 배경을 적용했다. 플러그 버튼에도 같은 송수신 흐름을 적용하는 것이 실습이었다. [11시 전사본 16~43분](<26 11 23/lecture/26 11 23 11~_original.txt>) · [QString](https://doc.qt.io/qt-6.8/qstring.html)
- **테스트 순서**. 먼저 수신자에 자기 로그인 ID를 넣어 서버를 거친 송신·수신과 화면 갱신을 확인했다. 실제 장치 테스트에서는 할당받은 ID로 접속하고 램프 명령의 수신자를 `HMCON`으로 바꿔 조명 LED의 ON/OFF를 확인했다. 서버의 `IDLIST` 명령으로 접속 목록을 확인했다. 실습 장치의 두 번째 제어 기능은 가스 ON/OFF였으므로, 플러그 버튼의 ON/OFF 왕복은 자기 ID로도 확인했다. [11시 전사본 42~43분](<26 11 23/lecture/26 11 23 11~_original.txt>) · [12시 전사본](<26 11 23/lecture/26 11 23 12~_original.txt>)

## 14~15시 · Qt Charts로 센서값을 시간축에 표시

1. **차트 구성**. 탭 4에 Clear 버튼과 차트용 레이아웃을 만들고, 코드에서 `QChartView`를 레이아웃에 넣었다. qmake의 `.pro`에 `QT += charts`를 추가했다. `QLineSeries`를 `QChart::addSeries()`로 등록하고, `QPen`으로 선의 색과 굵기를 설정했다. 시연의 Y축 범위는 0~100이었다. [14시 전사본 05~21분](<26 11 23/lecture/26 11 23 14~_original.txt>) · [15시 전사본](<26 11 23/lecture/26 11 23 15~_original.txt>) · [선 스타일 보충 녹음](<26 11 23/lecture/음성 261123_150614_original.txt>) · [Qt Charts](https://doc.qt.io/qt-6.8/qtcharts-index.html)
2. **수신과 변환**. 센서 메시지의 값은 `조도@온도@습도` 순서다. 탭 2가 명령을 분류하고 `QStringList`를 시그널로 보내면, `MainWidget`의 연결을 통해 탭 4 수신 슬롯이 호출된다. 조도는 `toInt()`, 온도와 습도는 `toDouble()`로 읽는다. 강사는 조도 그래프를 시연했다. 임의 데이터를 검사할 때는 시각을 달리해 두 건 이상 보내면 선분을 확인하기 쉽다. [14시 전사본 23~38분](<26 11 23/lecture/26 11 23 14~_original.txt>) · [15시 전사본 05~07분](<26 11 23/lecture/26 11 23 15~_original.txt>)
3. **시간축과 초기화**. X축은 `QDateTimeAxis`를 사용하고 시작 시각부터 10분 범위로 잡는다. 수신 시각을 `toMSecsSinceEpoch()`로 변환한 뒤 `append(x, y)`로 데이터를 추가한다. 시연에서 Clear는 조도 데이터를 지우고 현재 시각부터 시간축을 다시 설정했다. 계속 기록할 때는 시작 시각과 기존 데이터를 유지하고, 새 데이터가 범위를 벗어나면 X축 끝을 1분 단위로 연장하는 것이 과제다. [14시 전사본 07분·36~41분](<26 11 23/lecture/26 11 23 14~_original.txt>) · [15시 전사본](<26 11 23/lecture/26 11 23 15~_original.txt>) · [QDateTimeAxis](https://doc.qt.io/qt-6.8/qdatetimeaxis-qtcharts.html) · [QXYSeries](https://doc.qt.io/qt-6.8/qxyseries-qtcharts.html)

수신 로그에는 데이터가 보이는데 그래프가 비어 있으면 탭 2의 명령 판별, `MainWidget`의 연결, 탭 4 슬롯 호출, X축 범위를 순서대로 확인한다. 실습에서는 센서 명령의 철자를 점검하고, 서로 다른 시각에 조도값을 두 번 이상 보내 선이 그려지는지 확인했다. [14시 전사본 32~36분](<26 11 23/lecture/26 11 23 14~_original.txt>)

## 11월 24일 오후 평가 준비

- 조도 예제를 확장해 **조도·온도·습도 선 3개**를 한 차트에 표시한다. 선마다 색과 이름을 지정해 구분한다.
- **Clear**를 누르면 세 시리즈의 데이터를 모두 지우고, X축을 현재 시각부터 다시 10분 범위로 설정한다.
- 수신 시각이 X축 범위를 벗어나면 **시작 시각과 누적 데이터는 유지하고 끝 시각만 1분씩 연장**한다.
- 강사는 다음 날 평가 실습에서 새 프로젝트를 만들고 화면을 약 3개 구성하는 방향도 안내했다.

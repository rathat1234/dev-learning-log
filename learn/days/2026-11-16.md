# 2026년 11월 16일 C++ 수업 정리

## 상속과 업캐스팅·다운캐스팅

`Point`는 좌표를 관리하고, `ColorPoint`와 `GrayPoint`는 `Point`에 각자 필요한 멤버를 추가한다. 공개 상속 관계에서는 두 파생 클래스의 주소를 모두 `Point*`로 받을 수 있다. 수업에서는 이 성질을 이용해 여러 종류의 점을 하나의 함수에 넘겼다.

| 표현 | 동작 |
| --- | --- |
| `Point* p = &colorPoint;` | **업캐스팅**. 포인터로 같은 객체 안의 `Point` 부분을 가리킨다. 참조에도 같은 변환을 적용할 수 있다. |
| `p->showPoint()` | `Point`에 선언된 멤버를 호출할 수 있다. `showPoint()`가 가상 함수면 실제 객체 타입의 오버라이드를 호출한다. |
| `p->showColorPoint()` | `Point`에 선언되지 않은 파생 클래스 전용 함수라면 컴파일 오류가 난다. |
| `dynamic_cast<ColorPoint*>(p)` | **다운캐스팅**. `Point`가 가상 함수를 가진 다형 클래스일 때 실제 객체에 `ColorPoint` 부분이 있는지 확인할 수 있다. 포인터 변환이 실패하면 `nullptr`이다. |

`static_cast<ColorPoint*>(p)`는 실제 객체 타입을 검사하지 않는다. 화면에 표시하는 동작만 타입별로 바꾸려면 `Point`의 `showPoint()`를 가상 함수로 두고 파생 클래스에서 오버라이드할 수 있다. `Point point = colorPoint;`처럼 값으로 복사하면 `Point` 부분만 새 객체에 담기는 **객체 슬라이싱**이 발생한다.

## 기본 클래스 생성자 호출 순서

- `A → B → C` 순서로 상속했다면 `C` 객체를 생성할 때 `A → B → C`, 소멸할 때 `C → B → A` 순서로 각 클래스의 생성자와 소멸자 본문이 실행된다.
- 파생 클래스의 초기화 리스트에서 기본 클래스의 생성자를 지정할 수 있다. 예를 들어 `B(int n) : A(n) {}`은 `A`에 `n`을 넘긴다. 기본 클래스 초기화를 생략하면 인수 없이 생성하려고 하므로, 호출 가능한 기본 생성자가 없으면 컴파일 오류가 난다.
- `TV → WideTV → SmartTV` 실습에서는 `SmartTV`가 초기화 리스트의 `WideTV(size, true)`로 화면 크기와 비디오 입력 여부를 전달한다. `WideTV`의 `TV(size), videoIn(videoIn)`은 화면 크기를 `TV`에 맡기고 비디오 입력 여부를 초기화한다. `SmartTV`는 자신의 IP 주소를 초기화한다. `std::boolalpha`를 쓰면 비디오 입력 여부가 `1` 대신 `true`로 표시된다.

## 다중 상속과 가상 상속

`class MusicPhone : public MP3, public MobilePhone`처럼 둘 이상의 기본 클래스를 가질 수 있다. 수업에서는 `MusicPhone`에서 재생과 전화 기능을 함께 사용하고, `Calculator`에서 `Add`와 `Subtract`를 상속해 `+` 또는 `-`에 따라 각 기본 클래스의 `protected` 연산을 불렀다. 직접 상속한 기본 클래스의 초기화 순서는 클래스 선언의 기본 클래스 목록을 따른다.

`In`과 `Out`이 모두 `IO`를 상속하고 `InOut`이 `In`과 `Out`을 상속하면, 일반 상속에서는 `InOut`에 `IO` 부분이 두 개 생긴다. `IO::mode`에 접근할 때 어느 경로의 값을 쓸지 모호해질 수 있다. 두 중간 클래스가 `IO`를 가상 상속하면 `InOut`은 하나의 `IO` 부분을 공유한다.

```cpp
struct IO    { int mode = 0; };
struct In    : virtual public IO {};
struct Out   : virtual public IO {};
struct InOut : public In, public Out {};
```

가상 기본 클래스 `IO`를 초기화할 책임은 맨 아래에서 실제로 만드는 클래스인 `InOut`에 있다.

## 함수 이름 가림, 오버라이딩, 동적 바인딩

| 상황 | `Base* p = &derived;`에서 `p->draw()`를 호출한 결과 |
| --- | --- |
| `Base::draw()`가 일반 멤버 함수 | 포인터의 선언 타입에 따라 `Base::draw()`를 호출한다. 파생 클래스의 같은 이름은 파생 클래스에서 기본 클래스의 이름을 가릴 수 있다. |
| `Base::draw()`가 가상 함수이고 `Derived`가 오버라이드 | 포인터가 가리키는 실제 객체의 `Derived::draw()`를 호출한다. |
| `p->Base::draw()`처럼 클래스 이름으로 지정 | 가상 함수여도 지정한 `Base::draw()`를 직접 호출한다. |

- **오버로딩**은 같은 이름에 매개변수 목록이 다른 함수를 두고 호출 인수에 맞는 후보를 컴파일 시점에 고르는 것이다. **오버라이딩**은 상속받은 가상 함수에 파생 클래스의 구현을 제공하는 것이다.
- 파생 클래스에서는 `virtual`을 반복하지 않아도 가상 함수의 속성이 이어진다. `void draw() const override`처럼 `override`를 쓰면 매개변수나 `const`가 달라 오버라이드에 실패했을 때 컴파일러가 알려준다. 반환형은 일반적으로 같아야 하며, 클래스 포인터·참조의 공변 반환형에는 예외가 있다.
- `Base*`로 `new Derived`로 만든 객체를 삭제할 때 기본 클래스 소멸자를 `virtual ~Base() = default;`처럼 가상으로 선언한다. 그러면 파생 클래스와 기본 클래스 소멸자가 차례로 실행된다. 이 상황에서 기본 클래스 소멸자가 비가상이면 일반적인 `delete`의 동작은 정의되지 않는다.

## 순수 가상 함수와 추상 클래스

`virtual void draw() const = 0;`에서 `= 0`은 순수 가상 함수를 선언한다. 순수 가상 함수가 남아 있는 클래스는 추상 클래스다. 추상 클래스의 객체는 직접 생성할 수 없지만, 그 타입의 포인터와 참조로 구체적인 파생 객체를 다룰 수 있다. 추상 클래스에도 생성자, 데이터 멤버, 구현이 있는 일반 함수나 가상 함수를 둘 수 있다.

계산기 실습에서는 `Calculator`가 `add`, `subtract`, `average`를 순수 가상 함수로 선언하고 `GoodCalc`가 세 함수를 구현했다. 배열 `{1, 2, 3, 4, 5}`의 평균은 `3`이다. `GoodCalc`에서 하나라도 구현을 빠뜨려 해당 함수가 순수 가상으로 남으면 `GoodCalc`도 추상 클래스다. 다른 실습에서는 계산용 순수 가상 함수를 `Adder`와 `Subtractor`가 각자 덧셈과 뺄셈으로 구현했다.

## 종합 실습 · 도형 연결 리스트

강의 예제에서 `Shape*`는 `Circle`, `Rect`, `Line`을 모두 가리킬 수 있다. `Shape::paint()`가 가상 함수 `draw()`를 호출하면 각 도형의 구현이 실행된다. 오후 예제의 `Shape::draw()`에는 기본 구현이 있고, 별도의 추상 클래스 연습에서는 선언을 `= 0`으로 바꿔 보았다.

`pStart`는 첫 도형을, `pLast`는 새 도형을 연결할 마지막 도형을 가리킨다. `add()`는 현재 객체의 `next`에 새 객체의 주소를 넣고 그 주소를 반환한다. 삭제할 때는 현재 객체를 해제하기 전에 다음 주소를 저장해야 한다.

```cpp
#include <iostream>

class Shape {
public:
    virtual ~Shape() = default;

    void paint() const { draw(); }

    Shape* add(Shape* next) {
        next_ = next;
        return next_;
    }

    Shape* getNext() const { return next_; }

protected:
    virtual void draw() const { std::cout << "Shape\n"; }

private:
    Shape* next_ = nullptr;
};

class Circle : public Shape {
protected:
    void draw() const override { std::cout << "Circle\n"; }
};

class Rect : public Shape {
protected:
    void draw() const override { std::cout << "Rectangle\n"; }
};

class Line : public Shape {
protected:
    void draw() const override { std::cout << "Line\n"; }
};

int main() {
    Shape* pStart = new Circle;
    Shape* pLast = pStart;
    pLast = pLast->add(new Rect);
    pLast = pLast->add(new Circle);
    pLast = pLast->add(new Line);
    pLast->add(new Rect);

    for (Shape* p = pStart; p != nullptr; p = p->getNext()) {
        p->paint();
    }

    while (pStart != nullptr) {
        Shape* next = pStart->getNext();
        delete pStart;
        pStart = next;
    }
}
```

출력은 `Circle → Rectangle → Circle → Line → Rectangle` 순서로 한 줄씩 나온다. 호출 흐름은 `Shape* → Shape::paint() → 실제 도형의 draw()`다.

## 복습 · 객체는 스택과 힙 중 어디에 놓일까

수업의 `Point`와 `ColorPoint`를 떠올리면 된다. 함수 안에서 `ColorPoint local;`로 선언하면 지역 객체 `local`은 **자동 저장 기간**을 갖고, 보통 함수의 스택에 놓인다. 함수 안에서 `Point* p = new ColorPoint;`라고 쓰면 지역 변수 `p`에는 주소가 저장되고, 그 주소에 있는 `ColorPoint` 객체는 **동적 저장 기간**을 갖는다. 일반적인 `new`는 그 객체의 공간을 힙에서 할당한다.

| 코드 또는 부분 | 일반적인 위치 | 언제 사라지나 |
| --- | --- | --- |
| 지역 선언 `ColorPoint local;` | 스택의 `ColorPoint` 객체 | 블록을 벗어날 때 소멸자가 자동으로 실행된다. |
| 지역 선언 `Point* p = new ColorPoint;`에서 `p` | 스택의 포인터 변수 | 블록을 벗어날 때 포인터 변수의 수명이 끝난다. |
| 같은 줄의 `new ColorPoint`로 만든 객체 | 힙의 `ColorPoint` 객체 | 올바른 `delete`가 실행될 때 소멸하고 저장 공간이 반환된다. |

```text
스택
  local  [ColorPoint 객체 안에 Point 부분과 색상 멤버가 있음]
  p      [주소] ──────────────────┐
                                 ▼
힙           [다른 ColorPoint 객체 안에 Point 부분과 색상 멤버가 있음]
```

`Point` 부분과 색상 멤버는 각각의 완성된 `ColorPoint` 객체 안에 있다. 객체 생성 시에는 `Point` 부분을 초기화하고, 색상 같은 파생 클래스의 멤버를 초기화한 뒤, `ColorPoint` 생성자 본문이 실행된다. 멤버가 `std::string`이라면 문자열 객체는 그 자리에서 관리되며, 문자 데이터가 길어지면 문자열 구현이 별도의 동적 공간을 쓸 수 있다.

스택과 힙은 일반적인 구현을 그린 것이다. C++에서 코드로 구분하는 기준은 **저장 기간**이다. 예를 들어 함수 안의 `static` 지역 변수는 정적 저장 기간을 가진다. [11월 16일 09시 전사본](<26 11 16/lecture/09.txt>) · [C++ 표준 초안의 저장 기간](https://eel.is/c++draft/basic.stc)

## 복습 · 왜 소멸자에 `virtual`을 붙일까

`Base* p = new Derived;`에서 포인터의 선언 타입은 `Base*`이고 실제 객체는 `Derived`다. `Base`의 소멸자가 가상이면 `delete p;`가 실제 객체에 맞는 `Derived` 소멸자부터 실행한다. 이어서 파생 클래스의 멤버와 기본 클래스 부분이 정리되고, 마지막에 동적 저장 공간이 반환된다.

```cpp
#include <iostream>

struct Base {
    Base() { std::cout << "Base 생성\n"; }
    virtual ~Base() { std::cout << "Base 소멸\n"; }
};

struct Derived : Base {
    Derived() { std::cout << "Derived 생성\n"; }
    ~Derived() override { std::cout << "Derived 소멸\n"; }
};

int main() {
    Base* p = new Derived;
    delete p;
}
```

출력 순서는 **Base 생성 → Derived 생성 → Derived 소멸 → Base 소멸**이다. 수업의 도형 연결 리스트에서 `delete pStart;`도 같은 상황이다. `pStart`의 선언 타입은 `Shape*`이고 실제 객체는 `Circle`, `Rect`, `Line`일 수 있으므로 `Shape`에 `virtual ~Shape() = default;`를 둔다. 별도 정리 코드가 없는 기본 클래스에서도 이렇게 가상 소멸자를 선언할 수 있다.

이 예제에서 `virtual`을 빼고 일반적인 `delete p;`를 실행하면 **정의되지 않은 동작**이다. 수업 시연에서 기본 클래스 소멸자만 출력된 것은 해당 실행에서 관찰한 결과다. `Derived local;`처럼 지역 객체를 직접 만들면 블록을 벗어날 때 컴파일러가 그 객체의 타입을 알고 `Derived`와 `Base`를 차례로 소멸시킨다. ### 스트림과 버퍼

**스트림**은 프로그램이 문자나 바이트를 순서대로 읽고 쓰는 인터페이스다. 스트림이 연결된 곳만 바꾸면 같은 연산을 키보드, 화면, 파일에 적용할 수 있다. **버퍼**는 읽거나 쓸 데이터를 잠시 모아 두는 공간이다. 작은 출력을 모아서 전달하면 매번 장치에 접근하는 비용을 줄일 수 있다.

| 스트림 | 보통 연결되는 곳 | 예 |
| --- | --- | --- |
| `std::cin` | 표준 입력 · 키보드 | `std::cin >> number;` |
| `std::cout` | 표준 출력 · 화면 | `std::cout << number << '\n';` |
| `std::cerr` | 표준 오류 · 화면 | `std::cerr << "파일 열기 실패\n";` |
| `std::ifstream`, `std::ofstream` | 각각 입력 파일, 출력 파일 | `std::getline(in, line);`, `out << number;` |

`'\n'`은 줄바꿈 문자를 출력한다. `std::endl`은 줄바꿈을 쓰고 이어서 **플러시**해 스트림의 출력 버퍼를 비우도록 요청한다. 줄바꿈이 필요할 때는 `'\n'`을, 같은 줄의 진행 메시지를 즉시 보여 주려면 `std::flush`를 쓸 수 있다. 기본 설정에서는 `cin`이 입력을 받기 전에 연결된 `cout`을 플러시하므로, 줄바꿈 없는 입력 안내도 먼저 보인다. [표준 스트림 객체](https://eel.is/c++draft/iostream.objects) · [출력 조작자](https://eel.is/c++draft/ostream.manip)

### `>>`, `getline`, `get`의 차이

- **`>>`는 자료형에 맞춰 읽는다.** `int`에 `42`를 읽으면 숫자 42가 저장된다. `std::string`에 읽으면 기본 설정에서 앞 공백을 건너뛰고 다음 공백 전까지 한 단어를 가져온다.
- **`std::getline(in, line)`은 줄 단위로 읽는다.** 줄 안의 공백까지 문자열에 담고, 끝의 개행은 스트림에서 소비한다.
- **`in.get(ch)`는 문자 하나를 그대로 읽는다.** 공백이나 개행도 읽는다. 여러 바이트는 `read`, 여러 바이트를 쓸 때는 `write`로 처리한다.

입력 순서가 **나이 ↵ 이름 ↵**이라면 `cin >> age`가 숫자만 읽은 뒤 첫 번째 개행이 남는다. 이어서 `getline`을 부르면 그 개행에서 바로 멈춰 빈 문자열을 얻는다. 숫자 줄의 나머지를 `ignore`로 버린 뒤 이름 줄을 읽으면 된다.

```cpp
#include <iostream>
#include <limits>
#include <string>

int main() {
    int age;
    std::string name;

    if (!(std::cin >> age)) {
        std::cerr << "나이를 숫자로 입력하세요.\n";
        return 1;
    }
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
    if (std::getline(std::cin, name)) {
        std::cout << name << " / " << age << '\n';
    }
}
```

첫 줄에 `20`, 둘째 줄에 `Kim Min Su`를 입력하면 `Kim Min Su / 20`이 출력된다. 파일에서도 동일한 방식으로 한 줄씩 읽을 수 있다. `while (std::getline(in, line))`은 읽기에 성공한 줄만 처리하며, 마지막 줄 끝의 개행이 생략되어도 줄 내용이 있으면 처리한다. `eof()`는 읽는 과정에서 파일 끝을 만났는지, `fail()`은 변환이나 읽기 등에서 실패 상태가 생겼는지 확인한다. 잘못된 숫자 입력을 받고 재시도할 때는 `clear()`로 상태를 풀고 `ignore()`로 남은 입력을 버린다. ### 같은 값도 파일에 쓰는 방식이 다르다

`out << 1234;`는 일반적인 십진 출력 설정에서 문자 `1`, `2`, `3`, `4`를 저장한다. 변수의 저장 바이트를 기록하려면 바이너리 모드로 열고 `write`에 데이터의 주소와 길이를 넘긴다. 파일 포맷을 직접 설계한다면 자료형의 크기, 바이트 순서, 실수 표현을 정해야 읽는 쪽에서 같은 값으로 복원할 수 있다. `std::ios::binary`로 열어도 `<< 1234` 자체는 십진 문자 출력이다.

바이너리 복사에서는 입력과 출력 파일을 모두 바이너리 모드로 열고 바이트를 그대로 옮긴다. 아래 코드에서 `copy.bin`은 새로 쓰므로 동명의 파일이 있으면 기존 내용이 지워진다.

```cpp
#include <fstream>

int main() {
    std::ifstream in("source.bin", std::ios::binary);
    if (!in) {
        return 1;
    }
    std::ofstream out("copy.bin", std::ios::binary);
    if (!out) {
        return 1;
    }

    char buffer[32];
    while (true) {
        in.read(buffer, sizeof buffer);
        const std::streamsize count = in.gcount();
        if (count > 0 && !out.write(buffer, count)) {
            return 1;
        }
        if (!in) {
            break;
        }
    }
    out.close();
    return in.eof() && !in.bad() && out ? 0 : 1;
}
```

파일이 42바이트라면 첫 읽기에서 32바이트, 두 번째에서 10바이트를 얻는다. 두 번째 `read`는 요청한 32바이트를 다 읽지 못해 실패 상태도 설정하지만, 이미 읽은 10바이트는 `gcount()`에 남으므로 먼저 저장한다. 이런 순서로 마지막 조각까지 복사한다.

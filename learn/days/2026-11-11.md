# C++ 객체 초기화·소멸과 배열 전달

설비별로 측정 설정을 보관하는 클래스를 만들어 생성자 선택과 멤버 접근을 확인했다. 객체 배열을 함수로 전달할 때 원소 수와 행의 폭이 타입에 어떻게 반영되는지도 정리한다.

학습일 **2026-11-11**

## 1. 객체 하나의 초기 상태를 정하는 방법

측정 설정에 기본 채널과 기본 주기를 두고, 필요하면 둘 중 일부를 생성자 인수로 받는다. 아래 클래스에서 인수의 개수로 오버로드가 결정된다. 인수가 적은 생성자들은 채널과 주기를 모두 받는 생성자에 초기화를 위임한다.

```cpp
// SamplingPlan.hpp
#ifndef SAMPLING_PLAN_HPP
#define SAMPLING_PLAN_HPP

class SamplingPlan {
public:
    SamplingPlan() : SamplingPlan(2, 15) {}
    explicit SamplingPlan(int channel) : SamplingPlan(channel, 15) {}
    SamplingPlan(int channel, int interval);

    void reschedule(int interval);
    int interval() const { return interval_; }

private:
    int channel_;
    int interval_;
};

#endif
```

```cpp
// SamplingPlan.cpp
#include "SamplingPlan.hpp"

SamplingPlan::SamplingPlan(int channel, int interval)
    : channel_(channel), interval_(interval) {}

void SamplingPlan::reschedule(int interval) {
    interval_ = interval;
}
```

- 생성자의 이름은 클래스 이름과 같고 반환형을 적지 않는다. 기본 생성자는 인수 없이 부를 수 있는 생성자다. 사용자가 생성자를 선언하지 않으면 일반적으로 컴파일러가 기본 생성자를 암시적으로 선언한다. 인수가 필요한 생성자만 추가하면 인수 없이 생성하는 경로도 필요에 따라 명시해야 한다.
- 멤버는 생성자 본문에 들어가기 전에 클래스의 선언 순서대로 초기화된다. 위임 생성자에서는 대상 생성자가 끝난 뒤 위임한 생성자의 본문이 실행된다.
- 헤더 가드는 한 번역 단위에서 헤더 내용을 중복 처리하는 일을 막는다. 이를 지원하는 컴파일러에서는 `#pragma once`도 쓸 수 있다. 헤더를 포함하는 호출 파일과 `SamplingPlan.cpp`를 함께 빌드하면 클래스 밖에서 정의한 함수까지 링크된다.

## 2. 접근 권한과 객체가 끝나는 시점

`SamplingPlan plan{7};`을 만든 뒤 `plan.reschedule(20)`을 호출하면 공개 인터페이스를 통해 비공개 상태를 변경한다. 객체는 `.`으로 접근한다. 주소를 가진 포인터에서는 `ptr->interval()`과 `(*ptr).interval()`이 같은 객체의 함수를 호출한다. 읽기 전용 함수에 객체를 넘길 때 `const SamplingPlan&`를 사용하면 기존 객체를 복사하지 않고 참조할 수 있다.

| 지정자 | 접근 범위 |
| --- | --- |
| `private` | 해당 클래스의 멤버와 친구 |
| `protected` | 해당 클래스와 파생 클래스의 멤버 및 친구. 파생 쪽에서 접근하는 대상에도 제약이 있다. |
| `public` | 호출하는 쪽에서도 접근 가능 |

기본 접근 지정자는 `class`에서 `private`, `struct`에서 `public`이다. 둘 다 생성자와 멤버 함수를 가질 수 있다. 일반적인 헤더에서 클래스 정의 안에 본문을 둔 `interval()`은 암시적으로 `inline`이다. 호출 위치에 본문을 실제로 펼칠지는 컴파일러가 정한다. 펼치면 호출 비용이 줄 수 있고 여러 위치에 복제되면 코드가 커질 수 있다.

객체의 수명이 끝날 때 인수와 반환형이 없는 소멸자가 실행된다. 소멸자를 직접 선언하지 않아도 컴파일러가 암시적으로 선언하며, 소멸 과정에는 멤버 객체 정리도 포함된다. 객체가 소유한 파일 같은 자원도 이 시점에 정리할 수 있다.

| 저장 기간 | 생성과 소멸 |
| --- | --- |
| 자동 지역 객체 | 블록 안의 선언에서 초기화되고, 블록을 떠날 때 생성의 역순으로 소멸한다. |
| 일반적인 전역 객체 | 같은 번역 단위에서 순서 있는 초기화 대상은 정의 순서대로 초기화된다. 일반적으로 프로그램 시작 과정에서 초기화되며 정상 종료 시 정리된다. |
| 동적 객체 | `new`로 생성하고 대응하는 `delete`로 소멸시킨다. |

## 3. 배열을 전달하면 남는 정보

```cpp
#include "SamplingPlan.hpp"
#include <cstddef>

int sumIntervals(const SamplingPlan* plans, std::size_t count) {
    int sum = 0;
    for (std::size_t index = 0; index < count; ++index) {
        sum += plans[index].interval();
    }
    return sum;
}

int sumRack(const SamplingPlan (*rack)[2], std::size_t rowCount) {
    int sum = 0;
    for (std::size_t row = 0; row < rowCount; ++row) {
        sum += sumIntervals(rack[row], 2);
    }
    return sum;
}

int main() {
    SamplingPlan rack[][2]{
        {SamplingPlan{4, 12}, SamplingPlan{}},
        {SamplingPlan{9}, SamplingPlan{11, 18}},
        {SamplingPlan{}, SamplingPlan{}}
    };
    const auto rows = sizeof(rack) / sizeof(rack[0]);
    return sumRack(rack, rows) == 90 ? 0 : 1;
}
```

- `SamplingPlan plans[4];`처럼 초기값을 생략하면 각 원소의 기본 생성자가 호출된다. 목록 초기화에서는 원소마다 다른 생성자를 호출할 수 있다.
- 1차원 배열을 위와 같은 포인터 매개변수로 전달하면 첫 원소의 주소가 넘어간다. `plans[index]`와 `*(plans + index)`는 같은 원소다. 포인터 매개변수에 `sizeof`를 적용하면 포인터 크기를 얻으므로 원소 수를 별도로 전달한다.
- 2차원 배열의 첫 원소는 한 행이다. `const SamplingPlan (*rack)[2]`와 매개변수의 `const SamplingPlan rack[][2]`는 같은 타입으로 해석된다. `rack + 1`은 한 행을 건너뛴다. `SamplingPlan* refs[2]`는 각각의 객체 주소를 저장하는 포인터 배열이다.

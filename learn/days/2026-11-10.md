# C++ 콘솔 입력과 클래스 분리 빌드

정수와 공백이 포함된 문자열을 함께 읽을 때 입력 위치가 어떻게 바뀌는지 확인했다. 클래스를 헤더와 구현 파일로 나누고, 서로 다른 객체가 각자의 상태를 유지하는 과정도 정리한다.

학습일 **2026-11-10**

## 1. 입력 스트림에서 다음 줄로 넘어가기

`std::cin >>`로 정수를 읽으면 다음 줄로 넘어가는 문자는 스트림에 남을 수 있다. 이 상태에서 `std::getline()`을 바로 호출하면 현재 줄의 나머지를 먼저 읽는다. 정수 뒤의 내용을 버리고 다음 줄 전체를 받는 형식이라면 `ignore()`로 줄바꿈까지 소비한다. 고정 길이 문자 배열에는 버퍼 크기를 인자로 받는 `std::cin.getline(buffer, capacity)`를 사용할 수 있다.

```cpp
#include <iostream>
#include <limits>
#include <string>

int main() {
    int lane;
    if (!(std::cin >> lane)) {
        return 1;
    }
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');

    std::string destination;
    if (std::getline(std::cin, destination)) {
        std::cout << '[' << lane << "] " << destination << '\n';
    }
}
```

첫 줄에 차선 번호 `6`, 다음 줄에 `North Depot`를 입력하면 `[6] North Depot`가 출력된다. `std::`는 표준 라이브러리 이름이 속한 범위를 나타낸다.

## 2. 각 객체가 가진 상태와 빌드 경계

배송 구역마다 별도의 미처리 건수를 관리한다고 가정한다. `DispatchQueue`의 `pending_`은 객체마다 따로 존재한다. 초기 건수는 생성자에서 정하고, 공개 멤버 함수 `addShipment()`를 호출한 구역의 건수만 증가한다.

```cpp
// DispatchQueue.hpp
#ifndef DISPATCH_QUEUE_HPP
#define DISPATCH_QUEUE_HPP

class DispatchQueue {
public:
    explicit DispatchQueue(int pending);
    void addShipment();
    int pending() const;

private:
    int pending_;
};

#endif
```

```cpp
// DispatchQueue.cpp
#include "DispatchQueue.hpp"

DispatchQueue::DispatchQueue(int pending) : pending_(pending) {}

void DispatchQueue::addShipment() {
    ++pending_;
}

int DispatchQueue::pending() const {
    return pending_;
}
```

```cpp
// main.cpp
#include "DispatchQueue.hpp"
#include <iostream>

int main() {
    DispatchQueue north{4};
    DispatchQueue south{11};
    north.addShipment();
    std::cout << north.pending() << ' ' << south.pending() << '\n';
}
```

출력은 `5 11`이다.

이 헤더를 포함한 호출 파일과 구현 파일을 각각 컴파일하면 목적 파일이 생긴다. 링크 단계에서는 호출이 가리키는 함수 정의와 라이브러리를 연결한다. 선언을 보고 호출을 컴파일했더라도, `DispatchQueue.cpp`에서 만든 목적 파일을 빼면 생성자나 멤버 함수의 정의를 찾을 수 없다. 클래스 밖에서 정의할 때 쓰는 `DispatchQueue::`는 함수가 어느 클래스의 멤버인지 지정한다.

## 3. 클래스 인터페이스를 확장하는 방법

- 클래스는 상태와 동작을 묶어 새 타입을 정의한다. `private` 멤버의 상태 변경은 `public` 함수로 제공하고, 파생 클래스에서 사용할 멤버에는 `protected`를 지정할 수 있다.
- 생성자는 클래스와 이름이 같으며 반환형 없이 객체의 초기 상태를 정한다.
- 상속은 기존 타입에서 파생 타입을 정의하는 방법이다. 파생 타입에서 기반 클래스의 가상 함수에 대응하는 구현을 제공하면 오버라이딩이 된다.
- 오버로딩은 같은 이름의 함수에 서로 다른 매개변수 목록을 두는 방식이다. 템플릿은 여러 타입에 적용할 함수나 클래스를 공통 형태로 정의한다.

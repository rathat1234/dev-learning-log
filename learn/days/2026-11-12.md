# C++ 객체 소유권, 참조 반환과 문자열 처리

동적으로 할당한 메모리를 누가 해제하는지, 객체를 복사했을 때 데이터가 공유되는지 확인했다. 같은 객체를 연속해서 수정하는 참조 반환과, 문자열을 입력받아 처리하는 방법도 정리한다.

## 1. 배열을 가진 객체의 복사와 해제

실행 중에 정해진 개수만큼 공간이 필요하면 `new T[count]`를 사용할 수 있다. 예를 들어 센서별 보정값을 보관하는 객체에서 배열의 소유권을 확인할 수 있다.

```cpp
#include <algorithm>
#include <cstddef>

class Calibration {
public:
    explicit Calibration(std::size_t count)
        : count_(count), offsets_(new int[count]{}) {}

    Calibration(const Calibration& source) : Calibration(source.count_) {
        std::copy_n(source.offsets_, count_, offsets_);
    }

    Calibration& operator=(const Calibration&) = delete;
    ~Calibration() { delete[] offsets_; }

    Calibration& set(std::size_t index, int offset) {
        this->offsets_[index] = offset;
        return *this;
    }

    int get(std::size_t index) const { return offsets_[index]; }

private:
    std::size_t count_;
    int* offsets_;
};

int main() {
    Calibration initial{3};
    initial.set(0, 8).set(2, -4);

    Calibration edited = initial;
    edited.set(0, 12);
    return initial.get(0) == 8 && edited.get(0) == 12 ? 0 : 1;
}
```

컴파일러가 제공하는 복사 생성자는 멤버를 각각 복사한다. 포인터 멤버를 그대로 복사하면 두 객체가 같은 배열을 가리킨다. 이런 얕은 복사에서는 한쪽의 변경을 다른 쪽에서도 읽게 되고, 두 객체가 같은 배열을 해제하면 이중 해제가 된다. 위의 깊은 복사는 각 객체가 배열을 별도로 할당한 뒤 요소 값을 옮긴다. C 문자열을 같은 방식으로 복사한다면 길이에 끝의 널 문자 한 바이트를 더해 할당한다. `Calibration edited = initial;`과 `Calibration edited(initial);`은 새 객체의 초기화다. 이미 생성된 객체에 `edited = initial;`을 쓰면 복사 대입을 호출하므로, 예제에서는 해당 연산을 삭제했다. 실제 소유 버퍼는 `std::vector<int>`로, 문자열은 `std::string`으로 표현하면 표준 라이브러리가 복사와 해제를 관리한다.

| 할당 | 결과와 대응하는 해제 |
| --- | --- |
| `new T{...}` | 객체 하나를 만든다. `delete`를 호출하면 그 객체가 소멸한다. |
| `new T[count]` | 배열을 만들고 첫 원소를 가리키는 포인터를 얻는다. 클래스 원소는 초기화를 따로 지정하지 않으면 기본 생성자를 호출한다. `delete[]`는 원소를 생성 역순으로 소멸시킨다. |

배열에서는 `plans[i].enable()`과 `(plans + i)->enable()`이 같은 원소에 접근한다. 예를 들어 장치 설정을 요청 개수만큼 생성한 뒤 각 원소의 활성 상태를 설정하고, 활성 장치 수를 집계한 뒤 배열을 해제할 수 있다. 단일 객체와 배열의 해제 방식을 맞추지 않거나 해제한 객체에 다시 접근하면 정의되지 않은 동작이 발생한다. `delete`는 포인터에 자동으로 `nullptr`를 넣지 않으며, 소유 포인터를 비워도 같은 주소를 저장한 다른 포인터는 계속 남는다. 해제 전 마지막 소유 포인터를 새 주소로 덮어쓰면 메모리가 누수된다. 일반 `new`의 할당 실패는 `std::bad_alloc` 예외로, `new (std::nothrow)`의 할당 실패는 널 포인터로 확인한다.

디버거에서는 포인터에 든 주소, 포인터 변수 자체의 주소, 역참조한 값을 각각 확인할 수 있다. 리틀 엔디언 환경에서 `std::uint16_t` 값 `0x6B24`를 메모리 창으로 보면 낮은 주소부터 `24 6B`로 나타난다.

## 2. 수정할 대상과 함수의 반환 방식

비정적 멤버 함수에서 `this`는 호출에 사용된 객체를 가리킨다. 정적 멤버 함수는 특정 객체 없이 호출할 수 있어 `this`가 없다. 예제의 `set()`은 `return *this;`로 객체 자신의 참조를 반환하므로 다음 `set()`도 같은 배열을 수정한다. 수정 가능한 참조는 대입 대상으로도 사용할 수 있다. 예를 들어 원소가 있는 배열에 대해 `sampleAt(buffer, 0) = 42;`를 쓰려면 `sampleAt()`이 첫 원소의 참조를 반환해야 한다. 함수가 종료되면서 소멸하는 지역 객체의 참조는 반환 후 사용할 수 없다.

| 매개변수 | 기존 객체를 넘겼을 때 |
| --- | --- |
| `T value` | 별도 매개변수 객체에 복사한다. 내부에서 매개변수를 바꾸어도 원본은 유지된다. |
| `T* ptr` | 주소를 복사한다. 유효한 주소라면 역참조로 원본에 접근할 수 있다. |
| `T& ref` | 원본에 직접 연결한다. 수정하면 원본이 바뀐다. |
| `const T& ref` | 기존 객체를 복사하지 않고 읽는 데 쓴다. |

예를 들어 `bool findEarliest(const int* times, int count, int& result)`는 기록이 없으면 `false`를 반환하고, 기록이 있으면 가장 이른 값을 `result`에 기록하고 `true`를 반환할 수 있다. 이렇게 하면 유효한 결과값이 `0`일 때도 실패와 구분된다. 두 값을 바꾸는 함수도 값 매개변수라면 복사본만 바뀌고, 포인터의 대상이나 참조에 대입하면 호출자의 값이 바뀐다.

C++17 이상에서 반환형이 `Calibration`인 함수가 `return Calibration{count};`로 같은 타입의 임시값을 직접 반환하면 반환 객체가 곧바로 생성된다. 이름 있는 지역 객체를 반환하면 컴파일러가 NRVO로 복사나 이동을 생략할 수 있다. 생성자와 소멸자에 진단 출력을 넣으면 두 반환 방식의 호출 흐름을 비교할 수 있다. [C++ 표준 초안의 복사 생략 규칙](https://eel.is/c++draft/class.copy.elision)

## 3. 문자열을 읽고 변환하는 연산

| 연산 | 확인할 동작 |
| --- | --- |
| `std::cin >> text`와 `std::getline(std::cin, text)` | 앞의 연산은 선행 공백을 건너뛴 뒤 다음 공백 전까지 한 단어를 읽고, 뒤의 연산은 줄바꿈까지 한 줄을 읽는다. 두 방식을 섞어 다음 줄을 읽으려면 남은 줄바꿈을 먼저 소비한다. |
| `size()`, `length()`, `capacity()` | 앞의 두 함수는 `char` 원소의 개수를 돌려준다. `capacity()`는 재할당 없이 저장할 수 있는 크기다. |
| `+=`, `append()`, `<`, `==` | 내용을 뒤에 붙이거나, 문자열을 사전식 순서와 동등 여부로 비교한다. |
| `std::stoi(text)`, `text.c_str()` | 각각 문자열에서 정수를 해석하거나 널 문자로 끝나는 문자열의 포인터를 얻는다. |

여러 보관함 코드를 비교해 사전식으로 가장 뒤에 오는 코드를 고를 수 있다. 코드 `"R7K2"`를 왼쪽으로 두 칸 순환시키려면 `code.substr(2) + code.substr(0, 2)`로 이어 붙여 `"K2R7"`을 얻는다. 한 바퀴만큼 순환하면 원래 순서로 돌아온다. 이동량을 문자열 길이로 나눈 나머지로 처리한다면 빈 문자열을 먼저 확인한다. 이 예시는 ASCII 코드에 적용한다. UTF-8 문자열에서 `char` 위치로 자르면 여러 바이트로 이루어진 글자가 중간에서 갈라질 수 있다.

## 4. 오버로드와 기본 인수

`logReading(int channel)`과 `logReading(int channel, double value)`처럼 이름을 공유하는 함수는 매개변수 목록으로 구별한다. 반환형만으로는 오버로드할 수 없다. 생성자에는 오버로드를 둘 수 있고, 일반 클래스의 소멸자는 인수 없는 형태로 선언한다. `void flushLog(int count = 4);`에서 `flushLog()`는 `flushLog(4)`와 같은 인수를 전달한다. 필수 인수를 남기는 `void record(int channel, bool verbose = false);`는 `record(6)`으로 호출할 수 있다.

헤더와 구현 파일을 분리하면 호출 코드에서 볼 수 있는 선언에 기본값을 둔다. 구현의 정의에서 같은 기본값을 다시 쓰지 않는다. `explicit Calibration(std::size_t count = 3);`처럼 기본 인수를 주면 인수 없이 생성할 수 있다. 이 선언과 별도의 인수 없는 생성자를 함께 두면 `Calibration plan;`에서 호출할 생성자가 모호해진다.

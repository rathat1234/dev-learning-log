# 2026년 11월 20일 C++·Qt 수업 정리

오전에는 Raspberry Pi의 물리 스위치와 화면의 체크박스가 같은 키 상태를 표시하도록 장치 제어 탭을 완성했다. 오후에는 `QTcpSocket`으로 메시지를 주고받는 탭을 만들었다. 마지막 응용 실습은 두 탭을 시그널과 슬롯으로 연결해 원격에서 LED를 제어하고 보드의 키 상태를 돌려보내는 것이었다.

## 09~10시 · 물리 키 입력과 8비트 상태 표시

- 전날 만든 LED 출력 경로를 다시 확인했다. 다이얼 값이 바뀌면 LCD 숫자와 진행 바가 갱신되고, LED·키 클래스가 그 값을 디바이스 파일에 쓴다. `QTimer`는 다이얼 값을 `0~255`에서 순환시켜 같은 경로를 사용한다. [09시 전사본](<26 11 20/lecture/09.txt>) · [11월 19일 정리](2026-11-19.md)
- Designer에서 키 8개를 `QGridLayout`에 `8, 7, 6, 5 / 4, 3, 2, 1` 순서로 배치하고, 키 상태를 두 자리 16진수로 보여 주는 `QLCDNumber`를 추가했다. 키 입력은 `QSocketNotifier::activated` → 디바이스 파일 읽기 → 키 번호를 담은 사용자 정의 시그널 → 장치 제어 탭의 슬롯 순으로 전달했다. 보드에서 키가 두 번 인식되는 증상이 나왔을 때는 로그를 찍고 드라이버를 바꿔 보며 입력 이벤트를 확인했다. [09시 전사본](<26 11 20/lecture/09.txt>) · [10시 전사본](<26 11 20/lecture/10.txt>) · [QSocketNotifier](https://doc.qt.io/qt-6.8/qsocketnotifier.html)
- 키 번호 `1~8`을 비트 위치 `0~7`에 대응시킨다. `1u << (keyNo - 1)`로 해당 비트의 마스크를 만들고 `keyState ^= mask`로 그 비트만 반전한다. 예를 들어 `00`에서 1번, 8번, 1번을 차례대로 누르면 `01 → 81 → 80`이 된다. [10시 전사본](<26 11 20/lecture/10.txt>)

## 11시 · 체크박스와 물리 스위치 동기화

1. `QGridLayout::itemAtPosition(row, col)`로 각 칸의 위젯을 찾아 체크박스 포인터를 저장한다. 화면의 첫 칸은 8번 키이므로, 배열에는 1번 키를 인덱스 0에서 찾을 수 있도록 역순으로 담았다. [11시 전사본](<26 11 20/lecture/11.txt>) · [QGridLayout](https://doc.qt.io/qt-6/qgridlayout.html#itemAtPosition)
2. `QButtonGroup::addButton()`으로 체크박스에 `1~8` ID를 부여하고 `setExclusive(false)`로 여러 키를 동시에 체크할 수 있게 한다. 물리 키를 누르면 슬롯에서 해당 체크박스의 `setChecked()`를 호출한다. 마우스로 체크박스를 누르면 `idClicked(int)`가 넘긴 ID로 해당 비트를 갱신한다. 두 슬롯에서 같은 값을 쓰도록 키 상태를 클래스 멤버로 옮기고 `0`으로 초기화했다. [11시 전사본](<26 11 20/lecture/11.txt>) · [QButtonGroup](https://doc.qt.io/qt-6/qbuttongroup.html)
3. 키 상태를 LED에도 반영하는 실습에서는 `QDial::setValue()`로 다이얼 값을 바꿨다. 이때 발생하는 `valueChanged(int)`가 LCD, 진행 바, 실제 LED 출력을 갱신한다. 시그널을 직접 호출한 경우에는 연결된 동작이 실행되어도 다이얼 위치가 그대로 남는 현상을 확인했다. [11시 전사본](<26 11 20/lecture/11.txt>) · [QAbstractSlider](https://doc.qt.io/qt-6.8/qabstractslider.html#valueChanged)

## 12시 · 초기화 버튼과 소켓 탭 UI

- **LED Clear**는 다이얼 값을 `0`으로 설정한다. **Key Clear**는 저장한 키 상태를 `0`으로 초기화하고, 체크박스를 모두 해제한 뒤 키 LCD에 `00`을 표시한다. [12시 전사본](<26 11 20/lecture/12.txt>)
- 두 번째 탭은 별도의 **Qt Designer Form Class**로 만들고 `MainWidget`의 `QTabWidget`에 넣었다. 위에는 서버 연결·해제와 수신 삭제 버튼을 배치했다. 가운데 `QTextEdit`에는 수신 내역을 표시하고, 아래 `QLineEdit` 두 개에는 수신자 ID와 보낼 메시지를 입력한다. [12시 전사본](<26 11 20/lecture/12.txt>)

## 14시 · TCP 연결과 메시지 송수신

기존 소켓 클라이언트 클래스를 재사용하고 qmake 프로젝트의 `.pro`에 `QT += network`를 추가했다. 서버 주소와 포트를 설정한 뒤 Qt 앱과 기존 Linux 클라이언트로 송수신을 확인했다. 실습 포트는 `5000`이었다. 같은 머신에서 실행한 서버는 `127.0.0.1`로 접속하고, 다른 장치의 서버는 그 장치의 IP를 사용한다. [14시 전사본](<26 11 20/lecture/14.txt>) · [QTcpSocket](https://doc.qt.io/qt-6.8/qtcpsocket.html)

| 기능 | 실습 흐름 |
| --- | --- |
| 서버 연결·해제 | 연결 버튼을 `checkable`로 설정했다. 켜면 확인을 거쳐 `connectToHost()`로 접속하고, `connected`가 오면 실습 서버에 로그인 정보를 보낸다. 끄면 연결을 해제한다. |
| 수신 | `readyRead` 뒤 소켓에서 바이트를 읽는다. `QString`으로 변환한 메시지가 소켓 탭의 슬롯에 도착하면, 끝의 `\n`을 제거하고 `QTime::currentTime()`으로 얻은 수신 시간을 붙여 `QTextEdit::append()`로 표시한다. 끝의 개행을 제거하면 수신 내역에 빈 줄이 추가되는 것을 막을 수 있다. |
| 송신 | 두 입력칸에서 `text()`로 값을 읽는다. 수신자 ID가 있으면 `[수신자ID]메시지`를 보내고, 비어 있으면 `[ALLMSG]메시지`를 보내 접속자 모두에게 전달한다. 소켓 클래스가 끝에 `\n`을 붙여 전송한 뒤 메시지 입력칸을 비운다. |
| Enter로 송신 | 메시지 입력칸의 `returnPressed()`를 송신 버튼의 `click()`에 연결해 같은 송신 동작을 실행했다. |

[14시 전사본](<26 11 20/lecture/14.txt>) · [QAbstractSocket](https://doc.qt.io/qt-6.8/qabstractsocket.html) · [QIODevice](https://doc.qt.io/qt-6/qiodevice.html#readyRead) · [QTime](https://doc.qt.io/qt-6.8/qtime.html#currentTime) · [QTextEdit](https://doc.qt.io/qt-6.8/qtextedit.html#append) · [QLineEdit](https://doc.qt.io/qt-6/qlineedit.html#returnPressed)

보드와 개발 PC의 Qt 버전이 다를 때는 연결할 시그널 이름을 확인한다. `QButtonGroup::idClicked(int)`와 `QAbstractSocket::errorOccurred(...)`는 Qt 5.15에 추가됐다. 그보다 오래된 Qt 5에서는 각각 `buttonClicked(int)`와 `error(QAbstractSocket::SocketError)` 시그널을 사용한다. 수업에서는 `QT_VERSION`을 기준으로 연결 코드를 나누는 방식도 살펴봤다. [11시 전사본](<26 11 20/lecture/11.txt>) · [14시 전사본](<26 11 20/lecture/14.txt>) · [Qt 5 버튼 그룹 소스](https://codebrowser.dev/qt5/qtbase/src/widgets/widgets/qbuttongroup.cpp.html#176) · [Qt 5 소켓 소스](https://codebrowser.dev/qt5/qtbase/src/network/socket/qabstractsocket.cpp.html#212)

## 15시 · 송신 버튼 상태와 가상 키보드

- 연결이 없을 때는 송신 버튼을 비활성화하고, 연결에 성공하면 활성화했다. 연결을 해제하면 다시 비활성화했다. [15시 전사본](<26 11 20/lecture/15.txt>)
- 데스크톱 환경 없이 프레임버퍼로 Qt 화면을 띄우는 보드에서도 입력할 수 있도록 기존 가상 키보드 클래스를 추가했다. 수신자 ID와 메시지 중 편집할 `QLineEdit`를 키보드 객체에 넘긴 뒤 화면에 키보드를 표시했다. 입력칸의 슬롯에서 사용하기 전에 키보드 객체가 생성되어 있어야 한다. 소스와 폼을 추가한 프로젝트는 보드에서 `qmake`를 다시 실행한 뒤 `make`로 빌드했다. [15시 전사본](<26 11 20/lecture/15.txt>) · [Qt Embedded Linux](https://doc.qt.io/qt-6.8/embedded-linux.html)

## 응용 실습 · 소켓과 LED·키 장치 연결

두 탭의 객체에 접근할 수 있는 `MainWidget`에서 탭 사이의 시그널과 슬롯을 연결하도록 과제가 제시됐다. 기존 탭 내부의 LED 출력 경로와 소켓 송신 경로를 재사용한다. [15시 전사본](<26 11 20/lecture/15.txt>)

1. **원격 클라이언트 → 보드 LED**. 원격 클라이언트가 Qt 앱에 `LED@0F`처럼 `LED@`와 두 자리 16진수 값을 보낸다. 소켓 탭에서 명령을 확인하고, `QString::toInt(&ok, 16)`으로 변환한 값이 `0~255` 범위인지 확인한 뒤 장치 제어 탭의 다이얼에 넘긴다. `0F`는 10진수 15이므로 하위 4개 LED에 해당한다. [15시 전사본](<26 11 20/lecture/15.txt>) · [QString::toInt](https://doc.qt.io/qt-6.8/qstring.html#toInt)
2. **보드 스위치 → 원격 클라이언트**. 물리 스위치를 누르면 장치 제어 탭이 갱신한 8비트 키 상태를 `01`, `80`, `FF`처럼 두 자리 16진수로 만들어 지정한 상대 ID로 보낸다. 원격 클라이언트에서 받은 값과 보드의 키 LCD 값이 같은지 확인한다. [15시 전사본](<26 11 20/lecture/15.txt>)

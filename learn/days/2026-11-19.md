# 2026년 11월 19일 C++·Qt 수업 정리

오전에는 Qt Widgets 앱을 코드로 만들고 시그널과 슬롯으로 버튼 동작을 연결했다. 오후에는 Qt Widgets Designer로 Raspberry Pi의 LED 제어 화면을 만들고, 타이머가 다이얼 값을 바꾸면 표시와 LED 출력이 함께 갱신되도록 구성했다.

## 09시 · Qt Widgets 예제와 빌드

- Qt는 여러 플랫폼을 대상으로 GUI를 개발할 수 있는 프레임워크다. 수업에서는 Qt Quick·QML을 소개한 뒤 C++ 기반 **Qt Widgets**로 실습했다. Qt Creator에서 체크박스 예제를 열어 위젯 동작을 확인하고, 이미지나 아이콘을 등록하는 리소스 파일 `.qrc`도 살펴봤다.
- **qmake** 실습에서는 `.pro`가 없는 예제에 `qmake -project`를 실행했다. 생성된 `.pro`에 `QT += widgets`를 추가하고 `qmake`로 Makefile을 만든 뒤 `make`로 빌드했다. 소스나 헤더를 추가하면 `.pro`의 `SOURCES`, `HEADERS`를 확인하고 qmake를 다시 실행한다.
- **CMake** 예제는 Linux 터미널에서도 빌드했다. 프로젝트 루트에서 `qt-cmake -S . -B build -G Ninja`와 `cmake --build build`를 차례로 실행하면 된다. 명령을 찾지 못하면 Qt의 `bin`과 Ninja가 설치된 경로를 `PATH`에서 확인한다.
- **`uic`**는 Designer의 `.ui`를 읽어 `ui_*.h`를 생성한다. **`moc`**는 `Q_OBJECT`가 붙은 클래스의 시그널과 슬롯 등에 필요한 메타 객체 코드를 생성한다. 두 도구는 빌드 시스템이 호출한다.

## 10~11시 · 앱의 실행 흐름과 버튼 연결

1. `main()`에서 `QApplication app(argc, argv)`를 먼저 생성한다. 위젯을 만든 뒤 `show()`로 창을 표시하고 `return app.exec();`로 이벤트 루프를 실행한다.
2. `QLabel`과 `QPushButton`을 부모 없이 만들면 각각 최상위 창이 된다. 수업에서는 `QWidget`을 상속한 `MyWidget`을 만들고, 생성자에서 라벨과 버튼에 `this`를 부모로 넘겨 같은 창에 배치했다. `resize()`로 크기를 정하고 `move()`로 자식 위젯의 위치를 바꿨다.
3. `QObject::connect(송신 객체, 시그널, 수신 객체, 슬롯)`으로 동작을 연결한다. 종료 예제에서는 버튼의 `clicked`가 발생하면 앱의 `quit()`를 호출했다. 하나의 시그널을 여러 슬롯에 각각 연결할 수도 있다.
4. Qt API에서 위젯 자체에 원하는 함수가 보이지 않으면 상속 관계를 확인한다. 예를 들어 `QLabel`의 `show()`와 `resize()`는 `QWidget`에서, `QPushButton`의 `clicked`와 `toggled`는 `QAbstractButton`에서 가져온다.

```cpp
// 앱 객체와 종료 버튼을 만든 뒤 연결한다.
QObject::connect(quitButton, &QPushButton::clicked,
                 &app, &QCoreApplication::quit);
```

수업에서는 `SIGNAL(...)`과 `SLOT(...)`을 사용하는 연결 문법도 다뤘다. 위 예제의 함수 포인터 문법에서는 컴파일러가 연결의 타입을 검사한다. `clicked(bool)`를 인자 없는 `quit()`에 연결할 수 있는 이유는 슬롯이 시그널의 뒤쪽 인자를 생략할 수 있기 때문이다. ## 12시 · 사용자 정의 시그널과 토글 버튼

- `MyWidget`에 `Q_OBJECT`를 두고, 사용자 정의 시그널은 `signals:`에 선언한다. 슬롯은 `private slots:` 등에 선언한 뒤 `.cpp`에서 구현한다. 실습에서는 `clicked → 사용자 정의 슬롯 → emit mySignal() → quit()` 순으로 종료 흐름을 연결했다.
- `<QApplication>`을 포함하면 `qApp`으로 현재 앱 객체에 접근할 수 있다. 위젯의 슬롯에서는 `qApp->quit();`로 앱 종료를 요청할 수 있다.
- 슬롯에서도 라벨을 조작할 수 있도록 라벨 포인터를 생성자의 지역 변수에서 클래스의 `private` 멤버로 옮겼다. 버튼을 누르면 `QLabel::setText()`로 문구를 바꿨다.
- 버튼을 ON/OFF로 전환하려면 `setCheckable(true)`를 설정하고 `toggled(bool checked)`를 연결한다. 체크되면 `true`, 체크가 풀리면 `false`가 전달된다. 슬롯에서 이 값을 받아 라벨에 ON 또는 OFF를 표시했다.

## 14시 · Designer로 LED 제어 탭 만들기

Qt Creator에서 **Qt Widgets Application**을 만들고 메인 위젯에 `QTabWidget`을 배치했다. 첫 번째 탭의 장치 제어 화면은 별도의 **Qt Designer Form Class**로 만들었다. 생성자의 `ui->setupUi(this)`로 폼을 초기화하면 `ui`를 통해 각 위젯에 접근할 수 있다. 장치 입출력을 맡는 LED·키 클래스는 폼 없이 헤더와 구현 파일을 사용한다.

| 화면 요소 | 설정 및 역할 |
| --- | --- |
| `QPushButton` | 타이머 시작·정지 버튼은 `checkable`을 켜고 상태에 따라 Start/Stop으로 표시한다. 종료용 Quit 버튼도 배치한다. |
| `QComboBox` | 타이머 간격을 밀리초 단위로 선택한다. 예제 값은 50, 100, 200, 500, 1000, 2000이다. |
| `QDial` | LED에 보낼 값을 `0~255` 범위에서 정한다. 기본 증분은 1이고 눈금과 `wrapping` 속성도 확인했다. |
| `QLCDNumber` | `digitCount = 2`, `mode = Hex`로 설정해 다이얼 값을 두 자리까지 16진수로 표시한다. |
| `QProgressBar` | 범위를 `0~255`에 맞춰 현재 값이 범위 내에서 어느 정도인지 표시한다. |

세로 레이아웃 안에 가로 레이아웃을 넣어 버튼과 표시 위젯을 묶고, `layoutStretch`로 각 위젯이 차지하는 공간의 비율을 조절했다. 코드에서 접근하거나 자동으로 슬롯을 연결할 위젯에는 `objectName`을 지정했다. [14시 전사본](<26 11 19/lecture/14.txt>) · [Designer 폼 사용](https://doc.qt.io/qt-6/designer-using-a-ui-file.html) · [QLCDNumber](https://doc.qt.io/qt-6/qlcdnumber.html)

## 16시 · 타이머로 다이얼과 LED 갱신

- **시작·정지** 버튼을 켜면 콤보박스의 `currentText()`를 읽고 `QString::toInt()`로 변환한 값을 `QTimer::start(ms)`에 전달한다. 버튼을 끄면 `stop()`을 호출한다.
- **값 증가**는 `QTimer::timeout`에 연결한 슬롯에서 처리한다. 현재 다이얼 값에 1을 더하고 `maximum()`을 넘으면 0으로 돌아간다. 결과를 `setValue()`로 넣으면 `valueChanged(int)`에 연결된 LCD 표시, 진행 바, LED 출력 경로가 같은 값을 받는다. 다이얼을 직접 돌려도 이 경로로 갱신된다.
- **간격 변경**은 콤보박스의 `currentTextChanged(const QString &)`에 연결한다. `isActive()`가 참이면 새 간격으로 타이머를 재시작하고, 정지 상태에서는 다음 시작 때 선택값을 읽는다. 실습에서는 `stop()` 후 `start(ms)`를 호출했다. Qt의 `start(ms)` 자체에도 재시작 동작이 있다.
- **슬롯 자동 생성**은 Designer에서 위젯을 우클릭하고 **Go to Slot**을 선택한 뒤 시그널을 고르는 방식으로 실습했다. 생성된 슬롯은 `on_<objectName>_<signalName>` 규칙으로 연결된다. Quit 버튼의 슬롯에는 `qApp->quit();`를 넣었다.

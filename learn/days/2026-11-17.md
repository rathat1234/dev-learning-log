# 2026년 11월 17일 C++ 수업 정리

09~12시 전사본 기준. 함수·클래스 템플릿에서 시작해 STL 컨테이너와 알고리즘, 표준 입출력과 파일 입출력으로 이어졌다.

## 09시 · 함수 템플릿과 클래스 템플릿

같은 동작을 자료형별로 여러 번 구현해야 할 때, 자료형이 들어갈 자리에 `T`를 두고 템플릿을 작성한다. `template <typename T>`와 `template <class T>`는 여기서 같은 뜻이다. 컴파일러는 호출 인수로부터 `T`를 추론하고 필요한 함수 템플릿을 인스턴스화한다. 수업에서는 템플릿을 작성하는 과정을 **일반화**, 구체적인 자료형을 적용하는 과정을 **구체화**라고 설명했다.

```cpp
#include <iostream>

template <typename T>
void mySwap(T& a, T& b) {
    T temp = a;
    a = b;
    b = temp;
}

int main() {
    int x = 4, y = 5;
    double a = 0.3, b = 12.5;
    mySwap(x, y);  // T = int
    mySwap(a, b);  // T = double
    std::cout << x << ' ' << y << '\n';
    std::cout << a << ' ' << b << '\n';
}
```

출력은 `5 4`, `12.5 0.3` 순서다. `T&`로 받으므로 원래 변수의 값이 바뀐다. 이 정의로 `mySwap(x, a)`를 호출하면 하나의 `T`에 `int`와 `double`이 각각 추론되어 컴파일 오류가 난다.

| 실습 | 자료형을 적용하는 위치 |
| --- | --- |
| 두 값 중 큰 값 반환 | 두 인수와 반환형에 같은 `T`를 쓴다. 수업에서 정수와 문자를 각각 비교했다. |
| 배열의 합 구하기 | 원소와 합의 자료형을 `T`로 두고, 원소 개수는 `int`로 받는다. |
| 원본 배열을 대상 배열에 복사 | 원본과 대상의 원소 자료형을 `T1`, `T2`로 따로 받는다. 예제로 `int` 배열을 `double` 배열에 복사했다. |
| `MyStack<T>` | 내부 배열, `push`의 인수, `pop`의 반환형에 `T`를 쓴다. `MyStack<int>`와 `MyStack<double>`은 원소 자료형이 다른 클래스다. |

`MyStack<T>`에서 마지막에 넣은 원소를 먼저 꺼낸다. 맨 위 원소의 인덱스 `tos`는 빈 상태에서 `-1`이며, `push`는 인덱스를 증가시켜 저장하고 `pop`은 그 위치의 값을 꺼낸 뒤 인덱스를 감소시킨다. 클래스 밖에서 멤버 함수를 정의할 때는 `template <typename T>`를 다시 쓰고 `MyStack<T>::push`처럼 소속을 지정한다.

## 10~11시 · STL 컨테이너, 반복자, 알고리즘

**컨테이너**는 데이터를 담고, **반복자**는 원소의 위치를 가리키며, **알고리즘**은 반복자로 전달받은 범위를 처리한다.

| 구성 요소 | 수업에서 사용한 방법 |
| --- | --- |
| `std::vector<T>` · `<vector>` | 원소가 연속으로 저장되는 가변 길이 컨테이너다. `push_back`으로 끝에 추가한다. `size()`는 현재 원소 수, `capacity()`는 재할당 없이 담을 수 있는 원소 수다. |
| `v[i]`, `v.at(i)` | 둘 다 인덱스의 원소에 접근한다. `at(i)`는 범위를 검사하고 범위를 벗어나면 `std::out_of_range`를 던진다. `v[i]`를 쓸 때는 유효한 인덱스를 전달한다. |
| `std::map<Key, Value>` · `<map>` | 키마다 값 하나를 관리한다. `find(key)`는 찾은 위치를 반환하며, 키가 없으면 `end()`를 반환한다. 맵은 기본적으로 키의 오름차순으로 순회한다. |
| `std::sort(first, last)` · `<algorithm>` | `[first, last)` 범위를 정렬한다. `first`부터 시작해 `last` 바로 앞에서 끝난다. `std::sort(v.begin(), v.end())`는 벡터 전체를 오름차순으로 정렬한다. |

- `begin()`은 첫 원소의 위치, `end()`는 마지막 원소 다음 위치다. `it != end()`인 동안 `*it`로 원소에 접근하고 `++it`로 다음 원소로 이동한다. 읽기 전용 순회에는 `cbegin()`과 `cend()`를 쓸 수 있다.
- 벡터 중간에 원소를 삽입하거나 삭제하면 뒤쪽 원소의 위치가 바뀐다. 벡터가 재할당되면 기존 반복자는 모두 무효가 된다.
- 맵 반복자에서 `it->first`는 키, `it->second`는 값이다. `insert`에 이미 들어 있는 키를 주면 기존 항목을 유지한다. `m[key] = value`는 새 키를 추가하거나 기존 값을 갱신한다. `m[key]`로만 접근해도 키가 없으면 항목이 생기므로 조회에는 `find`를 쓴다.

실습에서는 `vector<string>`에 이름 다섯 개를 한 줄씩 입력받아 문자열 비교로 가장 뒤에 오는 이름을 찾았다. 또 벡터의 원소를 반복자로 순회하며 두 배로 바꾸고, 맵으로 영한사전이나 상품 정보를 저장·검색·삭제했다. 마지막으로 벡터에 점수 다섯 개를 담고 `std::sort`를 호출했다.

## 11~12시 · 표준 스트림과 입출력 연산자

| 표현 | 동작 |
| --- | --- |
| `std::cin >> n` | 입력 문자를 읽어 `n`의 자료형에 맞게 변환한다. |
| `std::getline(std::cin, line)` | 개행까지 한 줄을 읽는다. 줄 안의 공백은 유지하고 끝의 개행 문자는 소비한다. |
| `std::cout << value` | 값의 자료형과 현재 출력 형식에 따라 문자를 출력한다. 오류 메시지는 보통 `std::cerr`를 사용한다. |
| `get`, `put` / `read`, `write` | 한 문자 또는 지정한 길이의 데이터를 형식 변환 없이 처리하는 데 쓴다. |
| `std::hex`, `std::fixed`, `std::setprecision`, `std::setw` | 진법, 실수 표기, 정밀도, 출력 폭 등을 지정한다. 수업에서 본 숫자 출력에서는 `setw`가 바로 다음 필드에 적용되고, 진법과 정밀도 설정은 변경할 때까지 유지된다. |

`std::cout << point`가 동작하도록 `operator<<(std::ostream&, const Point&)`를, `std::cin >> point`가 동작하도록 `operator>>(std::istream&, Point&)`를 정의했다. 수업에서는 비공개 좌표에 접근할 수 있게 `friend`로 등록했다. 두 함수가 받은 스트림을 참조로 반환하면 `std::cout << p << q`처럼 연속해서 쓸 수 있다. 같은 반환 형식으로 별표를 찍는 사용자 정의 출력 조작자도 만들었다.

## 12시 · 파일 입출력

`<fstream>`의 `std::ifstream`은 읽기, `std::ofstream`은 쓰기, `std::fstream`은 읽기와 쓰기에 사용한다. 콘솔과 같은 `>>`, `<<`, `std::getline`을 파일 스트림에도 적용할 수 있다. 수업에서는 이름·학번·학과를 파일에 쓰고 다시 읽는 흐름을 다뤘다.

| 열기 모드 | 동작 |
| --- | --- |
| `std::ios::in` / `std::ios::out` | 읽기 / 쓰기로 연다. |
| `std::ios::app` | 쓸 때마다 파일 끝에 추가한다. |
| `std::ios::ate` | 처음 열 때 위치를 파일 끝으로 옮긴다. 연 뒤에는 위치를 다시 옮길 수 있다. |
| `std::ios::trunc` | 열 때 기존 내용을 비운다. |
| `std::ios::binary` | 바이너리 모드로 연다. Windows의 일반 텍스트 모드에서는 출력 `\n`이 파일에 `\r\n`으로 저장되며, 바이너리 모드에서는 `\n` 한 바이트가 그대로 저장된다. |

바이너리 파일 복사 실습에서는 `get`과 `put`으로 한 바이트씩 옮기는 방식과, `read`와 `write`로 여러 바이트를 옮기는 방식을 비교했다. 마지막 블록에서는 요청한 길이보다 적게 읽을 수 있으므로 `read` 직후 `gcount()`로 실제 읽은 길이를 확인해 그만큼 쓴다. 예를 들어 32바이트 단위로 42바이트 파일을 읽으면 각각 32바이트와 10바이트를 쓴다.

스트림 버퍼, `>>` 다음에 `getline`을 쓸 때의 주의점, 파일 끝 처리와 바이너리 복사 코드는 [11월 16일 정리의 스트림 복습](2026-11-16.md)에 이어서 정리했다.

# 입출력 다중화와 이벤트 처리

- 학습일: 2026-11-24
- 학습 범위: 413~446쪽 (446쪽은 판독 불가, 413~445쪽 기준 정리)

## 1. 입출력 다중화

- 하나의 실행 흐름에서 여러 파일 디스크립터의 입출력 가능 상태를 감시하는 방식이다.
- 특정 장치의 블로킹 I/O 때문에 다른 장치의 이벤트 처리가 지연되는 문제를 줄일 수 있다.
- 준비된 장치를 확인한 후 실제 데이터 전송은 `read()` 또는 `write()`로 수행한다.

## 2. 사용자 공간의 이벤트 감시

| 구분 | select() | poll() |
| --- | --- | --- |
| 감시 대상 | 파일 디스크립터 집합 | `pollfd` 배열 |
| 결과 확인 | `FD_ISSET()` | `revents` 비트 검사 |
| 대기 시간 | `timeval` | 밀리초 단위 |
| 주의점 | 집합 재설정, FD_SETSIZE 제한 | 감시 배열 순회 비용 |

- `pollfd`의 `fd`는 감시 대상, `events`는 관심 조건, `revents`는 실제 반환된 상태를 나타낸다.
- `POLLIN`은 읽기 준비, `POLLOUT`은 쓰기 준비를 의미한다.
- `POLLERR`, `POLLHUP`, `POLLNVAL`은 요청하지 않아도 결과에 포함될 수 있다.
- `poll()`은 준비된 배열 항목 수를 반환하며, 0은 시간 초과, -1은 시스템 호출 오류를 뜻한다.
- `select()`의 `exceptfds`는 일반적인 오류 전체가 아니라 예외적 상태를 감시한다.

## 3. 커널 드라이버의 이벤트 연동

- `file_operations.poll`은 현재 장치의 입출력 준비 상태를 비트 마스크로 전달한다.
- `poll_wait()`는 감시 대상 대기 큐를 커널에 연결한다. 이 함수 자체가 태스크를 재우는 것은 아니다.
- 장치가 준비되지 않았다면 커널은 요청 조건과 제한 시간에 따라 태스크를 대기시킬 수 있다.
- `wait_event_interruptible()`은 블로킹 I/O에서 조건이 충족될 때까지 대기하는 데 사용한다.
- `wake_up_interruptible()`은 대기 중인 태스크가 실행 가능해지도록 알린다. 즉시 실행을 보장하지는 않는다.

## 4. 인터럽트와 버퍼 관리

1. 하드웨어 이벤트가 발생하면 ISR에서 필요한 데이터를 확보한다.
2. 수신 데이터를 버퍼에 저장하고 준비 상태를 갱신한다.
3. 대기 큐에 이벤트를 알린다.
4. 커널이 준비 상태를 다시 검사하고 사용자 프로그램에 결과를 전달한다.
5. 사용자 프로그램이 데이터를 읽고 다음 이벤트를 기다린다.

- 원형 버퍼는 고정된 메모리에서 입력과 소비 시점의 차이를 흡수한다.
- 읽기 및 쓰기 위치를 별도로 관리하며, 용량 초과 시 데이터 폐기 또는 덮어쓰기 정책을 결정해야 한다.
- 인터럽트와 프로세스가 공유하는 버퍼는 경쟁 상태를 방지해야 한다.

## 5. 현대 커널 적용 시 주의점

- 커널 6.x에서 `.poll` 반환형은 `__poll_t`이다.
- 멀티코어 환경에서 로컬 인터럽트 비활성화만으로는 공유 데이터의 동시 접근을 막을 수 없다. 필요에 따라 `spin_lock_irqsave()` 등을 사용한다.
- 사용자 메모리 접근 함수는 잠들 수 있으므로 스핀락을 보유하거나 인터럽트를 비활성화한 상태에서 호출하지 않는다.
- 이벤트 확인 후에도 다른 실행 흐름이 먼저 데이터를 소비할 수 있다. 논블로킹 I/O와 `EAGAIN` 처리로 이를 대비한다.
- 레거시 프린터 포트 및 과거 커널 전용 구현은 현재 실습 코드에 그대로 적용하지 않는다.

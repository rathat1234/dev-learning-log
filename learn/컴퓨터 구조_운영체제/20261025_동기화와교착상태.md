# 프로세스 동기화와 교착 상태

## 1. 프로세스 동기화

프로세스 및 스레드의 **실행 순서를 조정하고 공유 자원의 일관성을 유지하는 것**을 동기화(Synchronization)라고 한다.

| 구분 | 의미 |
|---|---|
| 실행 순서 제어 | 작업이 정해진 선후 관계에 따라 실행되도록 보장 |
| 상호 배제(Mutual Exclusion) | 공유 자원의 임계 구역에 한 번에 하나의 실행 흐름만 진입하도록 제한 |

- 동기화 대상은 프로세스뿐 아니라 스레드 등 **동시에 실행되는 실행 흐름**을 포함한다.

### 1.1 공유 자원과 임계 구역

- **공유 자원(Shared Resource)**: 여러 실행 흐름이 접근하는 자원. 예: 공유 변수, 파일, 장치.
- **임계 구역(Critical Section)**: 공유 자원에 접근하며 동시 실행 시 충돌이 발생할 수 있는 코드 영역.
- **경쟁 상태(Race Condition)**: 실행 순서나 시점에 따라 결과가 달라지는 상황. 동기화가 없으면 데이터 일관성이 깨질 수 있다.

### 1.2 임계 구역 문제의 3가지 요구 조건

1. **상호 배제**: 한 실행 흐름이 임계 구역을 수행 중이면 다른 실행 흐름은 진입할 수 없다.
2. **진행(Progress)**: 임계 구역이 비어 있고 진입하려는 실행 흐름이 있다면, 진입 결정을 불필요하게 무기한 미뤄서는 안 된다.
3. **유한 대기(Bounded Waiting)**: 진입을 요청한 실행 흐름은 무한정 기다리지 않아야 한다.

## 2. 대표적인 동기화 기법

### 2.1 뮤텍스(Mutex)

**한 번에 하나의 실행 흐름만** 임계 구역에 들어가도록 보호하는 잠금 장치.

1. `lock` 또는 `acquire`: 임계 구역 진입 전 잠금 획득.
2. 임계 구역에서 공유 자원 사용.
3. `unlock` 또는 `release`: 작업 완료 후 잠금 해제.

- 잠금이 풀릴 때까지 반복 확인하는 방식은 **바쁜 대기(Busy Waiting)**이며, 대표적으로 스핀락에서 사용된다.
- **모든 뮤텍스가 바쁜 대기를 사용하는 것은 아니다.** 일반적인 뮤텍스 구현은 대기 중 스레드를 잠재워 CPU 낭비를 줄일 수 있다.
- 일반적으로 잠금을 획득한 실행 흐름이 해제해야 한다(소유권 개념).

### 2.2 세마포(Semaphore)

**사용 가능한 자원의 개수를 관리하거나 실행 순서를 맞추는** 동기화 도구.

| 종류 | 특징 |
|---|---|
| 이진 세마포 | 값이 0 또는 1. 상호 배제 또는 신호 전달에 활용 |
| 카운팅 세마포 | 여러 개의 동일 자원에 대한 동시 접근 수를 제어 |

- `S`: 이용 가능한 자원 수 또는 허가(permit) 수를 표현하는 값.
- `wait` (`P`, `down`): 허가를 얻어 진행하고, 허가가 없으면 대기.
- `signal` (`V`, `up`): 허가를 반환하거나 대기 중인 실행 흐름에 신호 전달.
- `wait`와 `signal`의 핵심 상태 변경은 **원자적(Atomic)**으로 수행되어야 한다.
- **블로킹 세마포**는 허가가 없으면 실행 흐름을 대기시키고, `signal` 시 대기 중인 실행 흐름을 깨워 준비 상태로 전환할 수 있다.
- 초기값이 0인 세마포를 이용하면 **A 작업 완료 후 B 작업 실행** 같은 순서 동기화도 가능하다.

### 2.3 모니터(Monitor)

**공유 데이터와 이를 다루는 연산을 하나로 묶고**, 내부 연산에 대한 상호 배제를 제공하는 구조.

- 외부에서는 모니터가 제공하는 연산을 통해서만 공유 데이터에 접근하도록 설계한다.
- 동시에 모니터 내부에서 실행할 수 있는 흐름을 하나로 제한한다.
- 조건 변수(Condition Variable)의 `wait`와 `signal`/`notify`로 특정 조건이 충족될 때까지 기다리거나 깨울 수 있다.
- 조건 변수의 `wait`는 **연관된 잠금을 해제하고 대기**하며, 깨어난 후 잠금을 다시 획득한다.
- 조건이 깨어난 직후에도 참이라는 보장은 없으므로 일반적으로 `if`가 아닌 **`while`로 조건을 재검사**한다.
- 모니터의 진입 순서가 항상 FIFO로 보장되는 것은 아니다.

### 2.4 동기화 기법 비교

| 구분 | 핵심 목적 | 특징 |
|---|---|---|
| 뮤텍스 | 상호 배제 | 잠금 소유권, 임계 구역 보호 |
| 세마포 | 자원 수 제한·순서 제어 | 허가 수를 관리, `wait`/`signal` |
| 모니터 | 동기화 구조화 | 공유 데이터·연산 캡슐화, 조건 변수 활용 |

## 3. 교착 상태(Deadlock)

둘 이상의 실행 흐름이 **서로 상대방이 보유한 자원을 기다리며 영원히 진행하지 못하는 상태**.

### 3.1 자원 할당 그래프(Resource Allocation Graph)

| 표시 | 의미 |
|---|---|
| 원 | 프로세스 |
| 사각형 | 자원 종류 |
| 사각형 내부의 점 | 해당 자원의 인스턴스 수 |
| 프로세스 → 자원 | 자원 요청(대기) |
| 자원 → 프로세스 | 자원 할당 |

- **자원 종류마다 인스턴스가 하나**라면 그래프에 사이클이 존재할 때 교착 상태가 발생한다.
- **인스턴스가 여러 개**라면 사이클은 교착 상태의 필요조건일 수 있지만, 사이클만으로 교착 상태를 확정할 수는 없다.

### 3.2 교착 상태의 4가지 필요조건

1. **상호 배제**: 적어도 일부 자원을 한 번에 하나의 프로세스만 사용할 수 있다.
2. **점유와 대기(Hold and Wait)**: 자원을 보유한 채 다른 자원을 기다린다.
3. **비선점(No Preemption)**: 보유 중인 자원을 강제로 회수할 수 없다.
4. **원형 대기(Circular Wait)**: 프로세스들이 서로의 자원을 원형으로 기다린다.

> 네 조건이 모두 성립해야 교착 상태가 **발생할 수 있다**. 네 조건이 성립한다고 언제나 교착 상태가 발생하는 것은 아니다.

## 4. 교착 상태 해결 방법

### 4.1 예방(Prevention)

교착 상태의 필요조건 네 가지 중 **최소 하나가 성립하지 않도록** 설계한다.

| 제거 대상 | 예방 방식 | 한계 |
|---|---|---|
| 상호 배제 | 가능한 자원을 공유 가능하게 설계 | 프린터 등 독점 사용이 필요한 자원에는 적용 어려움 |
| 점유와 대기 | 필요한 자원을 한 번에 요청하거나 기존 자원 반납 후 재요청 | 자원 활용률 저하, 기아 가능성 |
| 비선점 | 특정 상황에서 보유 자원을 회수하도록 설계 | 강제 회수가 불가능한 자원에 적용 어려움 |
| 원형 대기 | 자원 유형에 순서를 부여해 정해진 순서대로 획득 | 설계 제약, 자원 활용의 유연성 감소 |

### 4.2 회피(Avoidance)

자원 할당 요청 시 **안전 상태가 유지되는 경우에만** 자원을 할당한다.

- **안전 상태(Safe State)**: 모든 프로세스가 작업을 끝낼 수 있는 **안전 순서열**이 존재하는 상태.
- **안전 순서열(Safe Sequence)**: 현재 가용 자원과 앞으로 반납될 자원을 이용해 프로세스들을 차례로 완료할 수 있는 순서.
- **불안전 상태(Unsafe State)**: 안전 순서열이 없는 상태. **교착 상태가 반드시 발생했다는 뜻은 아니다.**
- 대표적인 회피 알고리즘: **은행원 알고리즘(Banker's Algorithm)**.

### 4.3 검출 후 회복(Detection and Recovery)

교착 상태의 발생을 허용하되, **검출한 뒤 자원을 회수하거나 프로세스를 종료**한다.

1. **자원 선점**: 일부 프로세스의 자원을 회수해 다른 프로세스가 진행하도록 한다. 재시작·롤백이나 기아 문제가 발생할 수 있다.
2. **프로세스 일괄 종료**: 관련 프로세스를 한꺼번에 종료한다. 빠르지만 작업 손실이 크다.
3. **프로세스 순차 종료**: 교착 상태가 해소될 때까지 하나씩 종료한다. 손실을 줄일 수 있으나 반복 검출 비용이 든다.

### 4.4 무시(Ostrich Algorithm)

교착 상태가 드물고 예방·회피·검출 비용이 더 크다고 판단되면 **운영체제가 특별한 조치를 취하지 않는 전략**을 선택할 수 있다.

## 5. 핵심 요약

1. **동기화**는 실행 순서 제어와 공유 자원 보호가 핵심이다.
2. **뮤텍스·세마포·모니터**는 목적과 사용 방식이 서로 다르다.
3. 교착 상태는 **상호 배제, 점유와 대기, 비선점, 원형 대기**라는 네 가지 필요조건과 관련된다.
4. 교착 상태 대응은 **예방, 회피, 검출 후 회복, 무시**로 구분한다.
5. **불안전 상태는 교착 상태와 동일하지 않다.**

# 연속 메모리 할당

## 1. 연속 메모리 할당

프로세스에 **물리 메모리의 연속된 공간을 할당**하는 방식이다.

## 2. 스와핑(Swapping)

오랫동안 실행되지 않는 프로세스 등을 **보조기억장치로 옮기고, 확보한 메모리 공간에 다른 프로세스를 적재해 실행**하는 방식이다.

| 용어 | 의미 |
| --- | --- |
| 스왑 영역(Swap Space) | 메모리에서 옮겨진 프로세스를 저장하는 보조기억장치의 일부 영역 |
| 스왑 아웃(Swap Out) | 프로세스를 메모리에서 스왑 영역으로 옮기는 것 |
| 스왑 인(Swap In) | 스왑 영역에 있던 프로세스를 다시 메모리로 옮기는 것 |

- 스왑 인할 때 프로세스가 **이전에 사용하던 물리 주소와 다른 위치**에 적재될 수 있다.
- 프로세스들이 요구하는 메모리의 총크기가 실제 물리 메모리보다 커도, 프로세스들을 **교대로 메모리에 적재하며 실행**할 수 있다.

## 3. 메모리 할당 방식

프로세스를 적재할 수 있는 빈 공간을 선택하는 대표적인 방식은 다음과 같다.

| 방식 | 선택 기준 | 특징 |
| --- | --- | --- |
| 최초 적합(First Fit) | 검색 중 처음 발견한, 프로세스를 담을 수 있는 빈 공간 | 적합한 공간을 찾으면 검색을 끝내므로 빠른 할당에 유리 |
| 최적 적합(Best Fit) | 프로세스를 담을 수 있는 빈 공간 중 가장 작은 공간 | 할당 직후 남는 공간을 최소화하지만, 작은 빈 공간이 많이 생길 수 있음 |
| 최악 적합(Worst Fit) | 빈 공간 중 가장 큰 공간 | 할당 후 남는 공간을 크게 확보하려는 방식 |

- 빈 공간 목록이 정렬되지 않았다면 **최적 적합과 최악 적합은 전체 목록을 검색**해야 한다.
- 최적 적합이라고 해서 전체 메모리 활용 효율이 항상 가장 좋은 것은 아니다.

## 4. 외부 단편화(External Fragmentation)

프로세스의 할당과 해제가 반복되면서 **사용 가능한 메모리가 여러 작은 빈 공간으로 흩어지는 현상**이다.

- 빈 공간의 총합이 충분해도, **하나의 연속된 공간이 부족하면** 프로세스를 적재하지 못할 수 있다.

### 4.1 압축(Compaction)

메모리에 적재된 프로세스들을 이동시켜 **흩어진 빈 공간을 하나의 큰 연속 공간으로 모으는 방법**이다.

- 프로세스의 실행을 일시 중지하고 메모리 내용을 옮겨야 하므로 **이동 비용과 실행 지연**이 발생한다.
- 어떤 프로세스를 어디로 옮길지 결정해야 하며, 이동한 위치에 맞게 주소를 조정해야 한다.

### 4.2 페이징(Paging)

프로세스의 메모리 공간을 일정한 크기의 **페이지**로 나누고, 물리 메모리의 같은 크기 단위인 **프레임**에 분산 배치하는 방식이다.

- 프로세스 전체를 연속된 물리 메모리에 적재할 필요가 없어 **외부 단편화를 해결**할 수 있다.
- 가상 메모리를 구현하는 대표적인 기법이다.

## 5. 핵심 요약

1. **연속 메모리 할당**은 프로세스에 연속된 물리 메모리 공간을 배정한다.
2. **스와핑**은 프로세스를 메모리와 보조기억장치 사이에서 옮겨 메모리 공간을 확보한다.
3. **최초 적합·최적 적합·최악 적합**은 빈 공간을 선택하는 기준이 다르다.
4. **외부 단편화**는 빈 공간이 흩어져 연속된 공간을 확보하기 어려운 문제다.
5. **압축**은 빈 공간을 모으고, **페이징**은 연속 배치의 필요를 없애 외부 단편화를 해결한다.

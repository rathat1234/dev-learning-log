# CPU 스케줄링 개요

## 1. CPU 스케줄링

CPU 스케줄링은 운영체제가 **실행 가능한 프로세스(또는 스레드)에 CPU 사용 순서와 시간을 배분**하는 작업이다. 목표는 응답 시간, 대기 시간, 처리량, 공정성 등을 상황에 맞게 개선하는 것이다.

### 1.1 프로세스의 특성 및 우선순위

| 구분 | 특징 |
| --- | --- |
| 입출력 집중(I/O-bound) 프로세스 | CPU 연산보다 입출력 요청·대기가 많은 프로세스 |
| CPU 집중(CPU-bound) 프로세스 | 입출력 대기보다 CPU 연산 비중이 큰 프로세스 |
| CPU 버스트(CPU burst) | 프로세스가 CPU에서 연속으로 실행되는 구간 |
| 입출력 버스트(I/O burst) | 입출력 작업을 수행하거나 그 완료를 기다리는 구간 |

- 운영체제는 프로세스의 특성과 스케줄링 정책에 따라 우선순위를 다르게 적용할 수 있다.
- 입출력 집중 프로세스의 응답성을 높이는 정책은 짧은 CPU 버스트 후 입출력을 기다리는 작업에 유리할 수 있다. **모든 운영체제가 입출력 집중 프로세스를 무조건 우선하는 것은 아니다.**
- Linux에서 `ps -el`로 프로세스의 우선순위 관련 값(`PRI`, `NI`)을 확인할 수 있다.
  - `nice -n 10 명령어`: 새 프로그램을 지정한 nice 값으로 실행한다.
  - `renice -n 10 -p PID`: 실행 중인 프로세스의 nice 값을 변경한다(권한 필요 가능).
  - 일반적인 Linux 스케줄링에서 **nice 값이 낮을수록 CPU 배분상 유리**하며, 범위는 `-20`부터 `19`까지이다. 이는 실시간 스케줄링 우선순위와는 다르다.

## 2. 스케줄링 큐

운영체제는 매번 전체 PCB를 검색하는 대신 프로세스의 상태와 자원 요청에 따라 **스케줄링 큐**를 관리한다.

| 큐 | 의미 |
| --- | --- |
| 준비 큐(Ready Queue) | CPU를 배정받아 실행하기를 기다리는 프로세스의 집합 |
| 대기 큐(Wait Queue) | 입출력 완료 또는 특정 이벤트 발생을 기다리는 프로세스의 집합 |

- 입출력이나 이벤트 대기가 끝난 프로세스는 일반적으로 **준비 상태**로 이동한다.
- 실제 구현에서 큐는 반드시 단순한 FIFO 자료구조일 필요는 없다.

## 3. 선점형과 비선점형 스케줄링

| 구분 | 선점형(Preemptive) | 비선점형(Non-preemptive) |
| --- | --- | --- |
| 실행 중 CPU 회수 | 운영체제가 강제로 회수할 수 있음 | 실행 중인 작업이 종료·대기·자발적 양보할 때까지 회수하지 않음 |
| 장점 | 응답성 향상, 다른 프로세스에 CPU 배분 가능 | 불필요한 문맥 교환이 상대적으로 적음 |
| 단점 | 문맥 교환 오버헤드 발생 가능 | 긴 작업이 짧은 작업을 오래 지연시킬 수 있음 |

선점형 스케줄링에서는 타임 슬라이스 만료나 더 높은 우선순위의 작업 등장 등이 CPU 회수 계기가 될 수 있다.

## 4. CPU 스케줄링 알고리즘

### 4.1 선입 선처리(FCFS, First-Come, First-Served)

- **비선점형**: 준비 큐에 들어온 순서대로 실행한다.
- 구현이 단순하지만 긴 작업이 앞에 있으면 짧은 작업도 오래 기다리는 **호위 효과(Convoy Effect)**가 발생한다.

### 4.2 최단 작업 우선(SJF, Shortest Job First)

- 예상 **다음 CPU 버스트가 가장 짧은 프로세스**를 먼저 실행한다.
- 일반적으로 **비선점형 SJF**를 뜻한다.
- 실행 시간을 정확히 미리 알기 어렵고 긴 작업이 계속 밀릴 수 있다.
- 선점형 대응 알고리즘은 **최소 잔여 시간 우선(SRTF)**이다.

### 4.3 라운드 로빈(RR, Round Robin)

- **선점형**: FCFS 방식에 **타임 슬라이스(타임 퀀텀)**를 적용한다.
- 정해진 시간이 지나도 완료되지 않은 프로세스는 준비 큐 뒤로 이동한다.
- 타임 슬라이스가 너무 짧으면 문맥 교환이 잦고, 너무 길면 FCFS에 가까워진다.

### 4.4 최소 잔여 시간 우선(SRTF, Shortest Remaining Time First)

- **선점형 SJF**로, **남은 CPU 실행 시간이 가장 짧은 프로세스**를 선택한다.
- 더 짧은 작업이 새로 준비되면 현재 프로세스를 선점할 수 있다.
- **고정 타임 슬라이스가 필수인 것은 아니며, RR과 동일한 방식은 아니다.**

### 4.5 우선순위 스케줄링(Priority Scheduling)

- 우선순위가 높은 프로세스에 CPU를 먼저 배정한다.
- 선점형 또는 비선점형으로 구현할 수 있다.
- 낮은 우선순위의 프로세스가 계속 실행되지 못하는 **기아(Starvation)** 현상이 생길 수 있다.
- **에이징(Aging)**: 오래 기다린 프로세스의 우선순위를 점진적으로 높여 기아를 완화한다.

### 4.6 다단계 큐(MLQ, Multilevel Queue)

- 준비 큐를 우선순위나 작업 유형에 따라 여러 개로 나눈다.
- 큐별로 서로 다른 스케줄링 알고리즘이나 타임 슬라이스를 적용할 수 있다.
- 일반적인 MLQ에서 프로세스는 **지정된 큐에 고정**되며, 상위 큐를 절대 우선하면 하위 큐에 기아가 발생할 수 있다.

### 4.7 다단계 피드백 큐(MLFQ, Multilevel Feedback Queue)

- MLQ와 달리 **프로세스가 큐 사이를 이동**할 수 있다.
- 일반적인 방식은 타임 슬라이스를 모두 사용하는 CPU 집중 작업의 우선순위를 낮추고, 대기 시간이 긴 작업의 우선순위를 높이는 것이다.
- 에이징이나 주기적 우선순위 재설정 등을 사용해 기아를 완화할 수 있다.
- 큐 이동 규칙·타임 슬라이스·우선순위 재조정 방법은 구현마다 다르다.

## 5. 알고리즘 비교

| 알고리즘 | 선점 여부 | 선택 기준 | 주요 특징·주의점 |
| --- | --- | --- | --- |
| FCFS | 비선점 | 준비 큐 도착 순서 | 단순하지만 호위 효과 발생 |
| SJF | 비선점 | 예상 CPU 버스트가 짧은 순서 | 평균 대기 시간 감소에 유리, 긴 작업 기아 가능 |
| RR | 선점 | 도착 순서 + 타임 슬라이스 | 응답성 향상, 타임 슬라이스 설정 중요 |
| SRTF | 선점 | 남은 CPU 실행 시간이 짧은 순서 | 짧은 작업에 유리, 긴 작업 기아 가능 |
| 우선순위 | 둘 다 가능 | 우선순위 | 기아 가능, 에이징으로 완화 |
| MLQ | 정책에 따라 다름 | 고정된 여러 큐의 우선순위·정책 | 큐마다 다른 알고리즘 적용 가능 |
| MLFQ | 보통 선점 | 실행·대기 이력에 따른 동적 큐 이동 | CPU·입출력 집중 작업에 유연하게 대응 |

## 6. 핵심 요약

1. **CPU 스케줄링**은 준비된 작업들에 CPU 사용 순서와 시간을 배분하는 운영체제 기능이다.
2. **선점형**은 실행 도중 CPU를 회수할 수 있고, **비선점형**은 종료·대기·양보 시까지 실행을 유지한다.
3. **FCFS → RR**: 도착 순서 기반에 타임 슬라이스를 추가한다.
4. **SJF → SRTF**: 가장 짧은 작업을 고르는 정책을 선점형으로 확장한다.
5. **우선순위·MLQ·MLFQ**는 우선순위와 큐 구조를 활용하며, **에이징**은 기아 현상을 완화하는 대표적인 기법이다.
